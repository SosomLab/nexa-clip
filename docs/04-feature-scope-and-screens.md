# 04 · 기능 범위 · 화면 구성 · 컨트롤 매핑

> **목적**: [03 경쟁 조사](03-competitive-landscape.md)에서 뽑은 기준선을 **기능 목록(FR)** 으로 확정하고,
> 그 기능을 **어느 화면이 어떻게 제공하는지**까지 잇는다. 화면·컨트롤 설계의 SSOT.
> **기반 구조 = `nexa-beep`**(크레이트 경계 · 자체 CPU 래스터라이저 · `plat` 포트) ·
> **컨트롤 계약 = `nexa-dir2` `ctl` + `nexa-beep` `nbeep-ctl`** 계승.
>
> **작성 2026-08-25.** 우선순위 범례: **P0 = 1차 필수**(이게 없으면 제품이 아니다) ·
> **P1 = 채택**(경쟁 우위) · **P2 = 후순위** · **✂ = 범위 밖**(하지 않기로 한 것).

---

## 0. 제품 한 줄과 설계 축

> **Nexa Clip** = *복사한 모든 것을, 세 OS에서 똑같은 화면으로, 암호화해 보관하고 한 번에 꺼내 쓰는 상주 도구.*

| 축 | 결정 | 출처 |
|---|---|---|
| **① 렌더** | 자체 CPU 래스터라이저 — Qt·WebView·Electron 금지. **3-OS 동일 화면** | [03 §6-2 ①](03-competitive-landscape.md#6-2-nexa-clip의-자리--세-개의-차별점) |
| **② 동작** | 시각은 한 벌, **동작 관례는 각 OS 네이티브**(수식 키·스크롤·컨텍스트 메뉴) | `nexa-beep` `docs/14 §1` |
| **③ 보안** | 기록은 **기본 암호화** · 민감 표식은 **캡처 자체를 안 한다** | [03 §6-2 ②](03-competitive-landscape.md#6-2-nexa-clip의-자리--세-개의-차별점) |
| **④ 무게** | 24시간 상주 — **유휴 RSS·바이너리 크기에 CI 게이트** | `nexa-dir2` DR-2 |
| **⑤ 경계** | OS 의존은 `plat` 하나에 격리. 나머지는 3타깃 공통 | `nexa-beep` `docs/01 §1` |
