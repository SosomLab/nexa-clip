# 12 · 클립보드 포맷 — Rich Text · 원본 형식 보존 · 평문 붙여넣기

> **사용자 요구(2026-08-25)**: *"워드나 PPT 등의 Rich Text 기능도 필요, 일반 텍스트로 붙여넣기 기능도 필요."*
>
> **결론**: 둘 다 **P0로 승격**한다. 다만 *"Rich Text를 지원한다"* 를 **HTML/RTF 보존으로만 구현하면 Word·PPT 왕복이 깨진다** —
> ★ **PPT 도형을 복사해 PPT에 붙여넣으면 도형이 아니라 그림이 된다.** 진짜 답은 **원본 형식을 그대로 들고 있는 것**이다([§3](#3--핵심--htmlrtf만으로는-부족하다)).
>
> 작성 2026-08-25 · [04 §1-1](04-feature-scope-and-screens.md#1-1-캡처-fr-c--클립보드에서-우리-쪽으로)·[§1-4](04-feature-scope-and-screens.md#1-4-붙여넣기활용-fr-p) 보강.

## 1. 먼저 이해할 것 — 클립보드는 **하나가 아니라 여러 벌**이다

Word에서 표를 하나 복사하면, 클립보드에는 **같은 내용의 여러 표현(representation)이 동시에** 올라간다.

```
Word에서 표 복사 → 클립보드
   ├─ CF_UNICODETEXT      "이름\t나이\n배상용\t49"       ← 가장 단순
   ├─ CF_HTML             <table><tr><td>…                ← 브라우저·메일이 받는다
   ├─ Rich Text Format    {\rtf1\ansi…                     ← 워드프로세서가 받는다
   ├─ CF_DIB / PNG        (표를 그린 그림)                  ← 그림판이 받는다
   └─ Object Descriptor
      Embed Source        (OLE 개체 원본)                   ★ Word가 표로 되살리는 것
```

> ★ **붙여넣는 앱이 자기가 아는 것 중 가장 좋은 것을 골라 간다.**
> 그래서 **우리가 몇 벌을 보관하느냐가 곧 붙여넣기 품질**이 된다.

## 2. OS별 실제 포맷 이름

| 내용 | **Windows** | **macOS (UTI)** | **Linux (MIME)** |
|---|---|---|---|
| 평문 | `CF_UNICODETEXT` | `public.utf8-plain-text` | `text/plain;charset=utf-8` |
| HTML | `CF_HTML`(★ 헤더 있음 — [§6](#6-크로스-os-전파-시-정규화)) | `public.html` | `text/html` |
| RTF | `Rich Text Format` | `public.rtf` | `text/rtf` · `application/rtf` |
| 이미지 | `CF_DIB` · `PNG` | `public.png` · `public.tiff` | `image/png` |
| 파일 목록 | `CF_HDROP` | `public.file-url` | `text/uri-list` |
| ★ **Word 개체** | `Object Descriptor` · `Embed Source` | `com.microsoft.word.doc` 계열 | `application/x-openoffice-*` |
| ★ **PPT 도형·슬라이드** | `Art::GVML ClipFormat` · `PowerPoint * Slides Package` | `com.microsoft.powerpoint.*` | — |
| ★ **Excel 범위** | `XML Spreadsheet` · `Biff12` · `Csv` | `com.microsoft.excel.*` | — |

> ⚠️ **정확한 포맷 문자열은 Office 버전·OS별로 다르다.** 위는 조사 시점의 대표값이고,
> **구현은 "이름을 안다"가 아니라 "있는 것을 전부 이름째로 보관한다"** 로 가야 한다([§4](#4-저장-모델--이름째로-전부-보관한다)).

## 3. ★ 핵심 — HTML/RTF만으로는 부족하다

### 3-1. 실패 시나리오

| 하는 일 | HTML/RTF만 보관 | 원본 형식 보관 |
|---|---|---|
| PPT에서 **도형 복사 → PPT에 붙여넣기** | ⚠️ **그림으로 떨어진다**(편집 불가) | ✅ **도형 그대로**(색·텍스트 편집 가능) |
| Excel **범위 복사 → Excel에 붙여넣기** | ⚠️ 수식이 **값·텍스트로** 떨어진다 | ✅ 수식·서식 유지 |
| Word **표 복사 → Word에 붙여넣기** | △ 표는 살지만 스타일·개체가 일부 소실 | ✅ 원형 유지 |
| Word → **메모장** | ✅ 평문 | ✅ 평문 |
| Word → **브라우저 입력창** | ✅ HTML | ✅ HTML |

> 👉 **"같은 앱으로 돌아갈 때"** 원본 형식의 가치가 드러난다. 그리고 그게 실사용의 상당 부분이다 —
> *PPT 슬라이드 A의 도형을 슬라이드 B에 붙여넣기*, *어제 복사한 Excel 범위를 오늘 다시 쓰기*.

### 3-2. 그래서 무엇을 하나

> ★ **[FR-C-6](04-feature-scope-and-screens.md#1-1-캡처-fr-c--클립보드에서-우리-쪽으로)(원본 포맷 원문 보존)을 P1 → P0로 올린다.**
> 이건 CopyQ가 잘하는 것이고([03 §5-2](03-competitive-landscape.md#5-2-장단점-상세--개발-방향-참고용)), **Maccy에는 없는 것**이다. 사용자에게 실질적 상향이 된다.

## 4. 저장 모델 — **이름째로 전부 보관한다**

```
ClipItem
├─ kind: RichText                      ← 표시·필터용 분류
├─ preview_text: "이름  나이  배상용 49"  ← 목록에 보이는 것(평문 파생)
├─ primary: text/plain                 ← 폴백 기준
└─ reps: [                             ★ 표현 목록 — 이름 그대로
     { fmt: "CF_HTML",           blob_id: … , bytes: 4_312 },
     { fmt: "Rich Text Format",  blob_id: … , bytes: 9_874 },
     { fmt: "Art::GVML ClipFormat", blob_id: …, bytes: 214_003 },
     { fmt: "CF_UNICODETEXT",    blob_id: … , bytes: 41 },
   ]
```

| 규칙 | 내용 |
|---|---|
| **F-1** | **알려진 포맷만 고르지 않는다.** 클립보드에 올라온 표현을 **이름과 함께 그대로** 저장한다(해석하지 않는다) |
| **F-2** | **평문은 반드시 하나 만든다** — 없으면 HTML/RTF에서 파생. **폴백이 항상 있어야 한다** |
| **F-3** | 각 표현은 [06](06-storage-design.md)의 **내용 주소 blob**으로 — 같은 바이트면 중복 저장 안 된다 |
| **F-4** | ⚠️ **크기 상한을 표현별로 건다** — Office 클립보드는 **수 MB**가 흔하다([§7](#7-용량--office-클립보드는-크다)) |
| **F-5** | **민감 표식은 표현 단위가 아니라 항목 단위**로 판정 — 하나라도 민감이면 항목 전체를 안 담는다(fail-closed) |

> ★ **F-1이 이 문서의 실질적 결론이다.** *"Word를 지원한다 / PPT를 지원한다"* 가 아니라
> **"올라온 것을 해석하지 않고 그대로 들고 있다가 그대로 돌려준다"** 가 되어야 앱마다 대응하지 않아도 된다.

## 5. 붙여넣기 모드 — **네 가지**

사용자 요구의 나머지 절반(*"일반 텍스트로 붙여넣기"*)이 여기 들어간다.

| # | 모드 | 동작 | 기본 키 (Win/Linux · mac) |
|:--:|---|---|---|
| **①** | **원본 그대로** | 저장한 **모든 표현을 다시 올린다** → 붙여넣는 앱이 최선을 고른다 | `Enter` · `Return` |
| **②** | ★ **평문으로** | `text/plain` **하나만** 올린다 | `Shift+Enter` · `⇧Return` |
| **③** | **서식만 제거, 줄바꿈 유지** | 스타일 제거 · 문단 구조 보존 | `Ctrl+Shift+Enter` · `⌘⇧Return` |
| **④** | **특정 형식 지정** | 표현 목록에서 골라서 붙여넣기(고급) | 팝업 메뉴 |

### 5-1. 기본 붙여넣기 형식 설정

| 설정 | 기본값 | 비고 |
|---|---|---|
| 기본 모드 | **① 원본 그대로** | 정보를 잃지 않는 쪽이 기본 |
| **항상 평문으로** | 끔 | ★ 켜면 ①↔② 가 뒤바뀐다(평문파 사용자용) |
| **앱별 규칙**(P2) | — | 예: 터미널·코드 편집기에는 항상 평문 |

> ★ **②는 P0다.** Maccy(`⌥⇧Enter`)·Ditto·CopyQ가 전부 제공하고, [03 §5-3](03-competitive-landscape.md#5-3-기능-매트릭스--채택-결정표)에서 4/6이다.
> Windows 내장(Win+V)에는 없어서 **PowerToys Advanced Paste를 따로 깔아야 하는** 대표적 결핍이다.

### 5-2. 목록에서 형식이 보여야 한다

```
📄 이름  나이  배상용  49                   Word · 2분 전
   [서식] [평문] [표]                        ← 보유 표현 배지
```

붙여넣기 직전에 **무엇으로 들어갈지** 알 수 있어야 한다([00 §2 ⑥](00-vision.md#-실수해도-되돌아간다) 되돌리기 원칙의 예방 버전).

## 6. 크로스 OS 전파 시 정규화

⚠️ **[08 자동 전파](08-clipboard-propagation.md)와 맞물리는 지점이다.** 서식은 OS마다 담는 방식이 달라 **그대로 옮기면 깨진다.**

| 표현 | 문제 | 처방 |
|---|---|---|
| **HTML** | ★ Windows `CF_HTML`은 **오프셋 헤더**(`StartHTML:`·`EndFragment:` …)가 앞에 붙는다. macOS `public.html`·Linux `text/html`은 **순수 HTML** | ★ **전파 시 헤더를 벗겨 순수 HTML로 정규화**하고, **받는 쪽 OS에서 다시 씌운다** |
| **RTF** | 대체로 호환되나 폰트 테이블·코드페이지 차이 | 그대로 전달 · 실패 시 평문 폴백 |
| **Office 원본 형식**(GVML·Embed Source 등) | ★ **상대 PC에 그 앱이 없으면 무의미**. 크기도 크다 | ★ **같은 OS·같은 앱 계열일 때만 전달**. 아니면 **HTML/RTF/평문까지만** 보내고 목록에 *"원본 형식은 이 기기에서 사용 불가"* 표시 |
| **평문** | 개행(CRLF/LF) | 저장은 LF 정규화, 붙여넣을 때 OS 관례로 복원 |

> ★ **원칙**: **잃는 것을 조용히 잃지 않는다.** 표현이 빠졌으면 목록에 보인다([08 §3 P-4](08-clipboard-propagation.md#3-2-권장--다적응형--목록-ui에-상태-표시)와 같은 규칙).

## 7. 용량 — Office 클립보드는 크다

PPT 슬라이드 하나를 복사하면 **수 MB**가 예사다(GVML + 미리보기 이미지 + 폰트 정보).

| 정책 | 값(초안) |
|---|---|
| 표현 1개 상한 | 예: 8MB 초과 시 **그 표현만 버리고** 나머지는 저장 |
| 항목 전체 상한 | 예: 32MB |
| 원격 전파 | ★ **메타 먼저 + 지연 가져오기**([08 §6](08-clipboard-propagation.md#6-lan과-원격을-다르게-다룬다)) |
| 보관 | 큰 표현은 **먼저 만료**(평문·HTML은 남기고 원본 형식만 회수) |

> ★ **"평문·HTML은 오래, 무거운 원본 형식은 짧게"** 라는 **표현별 차등 수명**이 이 문제의 핵심 처방이다.
> 항목 자체는 남으므로 사용자는 잃은 느낌을 받지 않는다.
