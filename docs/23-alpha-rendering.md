# 23 · 알파 렌더링 — 반투명을 어디까지, 어떻게

> **사용자 요청(2026-08-26)**: *"이번 렌더 적용 시에는 알파 적용을 통해 반투명한 기능도 구현할 수 있도록 기능을 개선해줘."*
>
> ★ **"반투명"은 서로 다른 두 가지다.** 섞어 놓으면 "왜 뒤가 안 비치지"에서 막힌다.
> 이 문서가 그 둘을 가르고, **무엇이 지금 되고 무엇이 플랫폼 작업인지**를 정한다.

---

## 1. 두 층 — 앱 안의 알파 vs 창 자체의 투명

| # | 층 | 무엇이 비치나 | 지금 상태 |
|:--:|---|---|:--:|
| **L1** | ★ **앱 안 알파 합성** | **우리가 이미 그린 픽셀**이 비친다 — 목록 위 오버레이, 시트 배경, 그림자, 스크롤바 | ✅ **구현됨** |
| **L2** | **창 자체 투명** | **뒤의 다른 창·바탕화면**이 비친다(macOS 사이드바 같은 vibrancy) | ☐ 플랫폼 작업 |

> ★ **L1이 UI가 실제로 쓰는 것의 대부분이다.** 오버레이·모달 딤·그림자·반투명 구분선은 전부 L1이다.
> L2는 **창 밖**이 비치는 것이라 성격이 다르다.

---

## 2. L1 — 앱 안 알파 합성 (구현됨)

### 2-1. 어휘

| API | 위치 | 용도 |
|---|---|---|
| `Surface::blend_px(x, y, color, coverage)` | `nclip-gfx` | 픽셀 하나 — 글리프 AA의 기초 |
| ★ `Surface::fill_rect_alpha(x, y, w, h, color, alpha)` | `nclip-gfx` | **반투명 사각형**(신규 08-26) |
| `Surface::blend_image*` | `nclip-gfx` | RGBA 이미지(straight alpha) |
| ★ `DrawCtx::fill_rect_alpha(rect, color, alpha)` | `nclip-ctl` | 위젯이 쓰는 어휘(신규 08-26) |
| `DrawCtx::fill_round_rect_alpha` · `stroke_round_rect_alpha` | `nclip-ctl` | 라운드 사각 + AA(기존) |

### 2-2. 설계 규칙

| # | 규칙 | 왜 |
|:--:|---|---|
| **A-1** | ★ **`alpha >= 1.0`이면 불투명 경로로 넘긴다** | 픽셀당 블렌드 비용을 아낀다. `fill_rect`는 `slice::fill`이라 훨씬 빠르다 |
| **A-2** | ★ **전경 색은 루프 밖에서 한 번만 분해**한다 | 픽셀마다 다시 쪼개면 큰 오버레이에서 그대로 비용이 된다 |
| **A-3** | **클리핑 규약은 불투명 경로와 동일** | 표면 밖에서 시작해도 패닉하지 않는다(테스트로 고정) |
| **A-4** | `DrawCtx`의 **기본 구현은 불투명 폴백** | 백엔드가 미구현이어도 **화면이 비지 않는다**(테스트 백엔드 배려) |
| **A-5** | ★ **알파는 테마 토큰이 아니라 인자**다 | 같은 색을 상황별로 다른 불투명도로 쓴다(딤 0.4 · 오버레이 0.92 · 구분선 0.25) |

### 2-3. 쓰는 자리

| 자리 | 알파(초안) | 비고 |
|---|---:|---|
| **모달 딤**(시트 뒤 배경 어둡게) | 0.45 | S4 항목 편집 · 승인 프롬프트 |
| **미리보기 패널 오버레이** | 0.92 | 목록 위에 떠서 뒤가 살짝 비친다 |
| **그림자** | 0.18~0.30 | 패널·팝업 가장자리 |
| **오버레이 스크롤바** | 0.35(유휴) → 0.75(호버) | macOS 방식 |
| 구분선·비활성 텍스트 | 0.25~0.5 | 색을 새로 만들지 않고 불투명도로 |

> ⚠️ **딤을 남용하지 않는다.** 클립보드 팝업은 **1.5초 안에 끝나는 화면**이라
> 모달을 자주 띄우면 그 자체가 비용이다([00 §2 ①](00-vision.md#-호출에서-완료까지-3초)).

## 3. L2 — 창 자체 투명 (플랫폼 작업 · 미구현)

**지금 구조로는 안 된다.** 이유를 정확히 적어 둔다.

```text
우리 픽셀 버퍼 = &mut [u32]  형식 0x00RRGGBB
                   ^^ 상위 8비트가 비어 있다 — softbuffer는 알파를 합성기에 전달하지 않는다
```

`winit::WindowAttributes::with_transparent(true)`를 켜도, **softbuffer가 올리는 버퍼에 알파 채널이 없어**
합성기(DWM·Quartz)가 뒤를 비출 근거가 없다.

### 3-1. OS별 실제 경로

| OS | 필요한 것 |
|---|---|
| **Windows** | `WS_EX_LAYERED` + **`UpdateLayeredWindow`** (프리멀티플라이드 알파 BGRA DIB를 직접 올린다) · 또는 DWM 블러(`DwmEnableBlurBehindWindow`) |
| **macOS** | `NSWindow.isOpaque = false` + `backgroundColor = clear` · vibrancy는 `NSVisualEffectView` |
| **Linux/X11** | 32비트 비주얼(ARGB) + 합성기 필요 |
| **Linux/Wayland** | 합성기가 알파를 지원 · 버퍼 포맷을 `ARGB8888`로 |

### 3-2. 판단 — 지금 하지 않는다

| 근거 | 내용 |
|---|---|
| **가치 대비 비용** | L2는 **미관**이고, [00 §2](00-vision.md#2--핵심-편의성-8--기능이-아니라-성질)의 편의성 8에 없다 |
| **경로가 갈린다** | `UpdateLayeredWindow`는 softbuffer 경로를 **대체**한다 — 렌더 파이프라인을 OS별로 두 벌 유지하게 된다 |
| ★ **가독성 위험** | 클립보드 목록은 **글자를 읽는 화면**이다. 뒤가 비치면 **대비가 무너져 읽기 어려워진다** — Maccy·CopyQ가 불투명한 이유 |
| 대안이 있다 | 팝업 **가장자리 그림자 + L1 오버레이**로 "떠 있는 느낌"은 충분히 난다 |

> 🔴 **필요해지면**: `nclip-plat`에 창 표면 포트를 하나 더 두고(불투명/투명 두 백엔드),
> **설정으로 켜는 옵션**으로 넣는다 — 기본은 불투명. → [D-53](#5-열린-결정)
