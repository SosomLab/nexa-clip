| # | 증상 | 조치 |

## 2026-08-27 (3차) — ★ 제품이 처음으로 "동작"한다 (T-14b)

```
$ nexa-clip watch
클립보드 감시: ok (win32-listener)
[3] 종류: Text · 표현 6개 · 미리보기: 한글 평문 확인
```

- ★ **Windows 클립보드 감시** — 메시지 전용 창 + 전용 스레드(`GetMessageW`가 블록 → 유휴 CPU 0).
  ⚠️ 클립보드는 한 번에 한 프로세스만 연다 → **재시도** · 핸들 포맷은 `GlobalLock` 금지.
- ★ **`nexa-clip watch`** — 복사할 때마다 무엇이 잡히는지 찍는다. **저장 경로와 같은 함수**를 쓴다.
- ★ **첫 실행에서 버그 넷** — 전부 *조용히 틀리는* 종류였다:
  ① `CF_UNICODETEXT`가 **UTF-16LE**(한글이 통째로 사라졌다) ·
  ② `DataObject` 하나가 텍스트를 리치로 · ③ **`CF_OEMTEXT` 누락** ·
  ④ *"벤더면 무조건 리치"* 가 **그림까지** 리치로.
- 설계 정정: `ClipSnapshot`이 **`RawRep`**(감시는 `blob_id`를 만들 수 없다) ·
  `capture`가 `RepInfo` 제네릭 · `Captured.keep`(인덱스) · `PreviewMissing::ThumbMissing`.

| 실기(Windows) | 결과 |
|---|:--:|
| 평문 · 색 · 파일 · 이미지 분류 | ✅ 자동 확인 |
| ⏳ **Word·Excel·Chrome·PPT 훑기** | 점검 요청([21 §1-2](21-manual-test.md)) |

## 2026-08-26 (14차) — ★ 캡처 파이프라인 (T-14a)

[27](27-capture-cases.md)의 규칙이 코드가 됐다 — `nclip-core::capture`.
★ **OS 호출·디코딩·파일 접근이 없는 순수 함수**라 실제 클립보드 없이 전부 테스트된다.

| 하는 일 | |
|---|---|
| `classify` | 표현 이름들 → 종류. ★ **순서가 전부**(파일 → 벤더 → HTML/RTF → 비트맵 → 텍스트) |
| `primary_index` · `thumbnail_source` | 사다리 꼭대기 · 미리보기 원본(PNG > DIBV5 > DIB) |
| `select_reps` | 용량 상한 — **필수는 안 버린다** · 버린 양을 알린다 |
| `capture` | 위를 묶어 `Captured`(종류 · 표현 · `Preview` · 버린 바이트) |

- ★ **벤더 포맷을 목록으로 알아보지 않는다** — *"아는 표준이 아니면 벤더"*.
  앱 이름 표는 영원히 늙는다. **모르는 포맷을 넣은 앱이 그걸 읽을 줄 아는 앱**이다.
- ⚠️ 그 규칙의 함정은 **곁다리**였다 — `CF_LOCALE` 하나로 맨 텍스트가 리치가 된다.
  `is_metadata_format`으로 걸러내고 테스트로 박았다.
- `ClipItem.preview`가 `String` → **`Preview`**(Text/Rich/Thumb/Files/**None(사유)**).
  ★ JPEG는 `미리보기 없음`이 아니라 **`JPEG`** 라고 적는다 — 못 그리는 것과 깨진 것을 구분한다.
- `primary`를 필드가 아니라 **파생값**으로 — `select_reps`가 표현을 버리면 인덱스가 밀린다.
- 문서의 네 케이스가 그대로 테스트 이름이 됐다(`case1_ppt_shapes` …).

## 2026-08-26 (13차) — 개수 설정을 숫자로

> *"Maximum items가 최대 보관 클립보드 수라면 숫자로 직접 지정하도록 숫자로 표현해줘. 200, 1000 등등"*

- ★ **`SettingKind::Number`** 신설 — 라벨을 번역하지 않는다. **후보 문자열이 곧 화면 값**이다.
- `store.max_items` = `200·500·1000·5000·10000` + 직접 입력(**10~100000**) · 기본 **1000**
- `ui.tray_recent_n` = `5·8·10·15·20` + 직접 입력(**3~20**) · 기본 **8**
  (같은 화면에서 하나만 숫자면 읽는 사람이 두 번 생각한다 — 함께 바꿨다)
- ⚠️ 범위를 벗어나면 **경고 + 직전 값으로 원복**(기존 검증 배선 그대로).
- 글꼴 크기는 **안 바꿨다** — 거기선 *작게/보통/크게* 가 사용자가 원하는 표현이다.

- ⚠️ **점검 화면이 거짓말을 하고 있었다** — `default view`가 `ViewMode::default()`를 찍어
  사용자가 뭘 바꾸든 영원히 `Compact`였다. **저장본을 읽도록** 고쳤다(영속을 터미널에서 검증 가능).

**실기 확인**(빌드 후 실제 실행)

```
settings        : ...\target\debug\data\settings.cfg (저장본 사용)
default view    : Rich (rich)
theme           : dark
max items       : 2500        ← 후보에 없는 직접 입력값이 살아 있다
tray recent     : 15
```

## 2026-08-26 (8차) — 공유 정책 정밀화 · 파일 내용 공유 설계

- **DR-29** — 범위와 승인을 분리. ★ **신뢰는 도달 허가일 뿐 수신 동의가 아니다** → 신뢰해도 기본 수동 승인, 자동 승인은 **사람 단위**. **재전파는 수신측 결정**(보내는 쪽이 정하면 A가 B의 기기 구성을 좌우한다).

**핵심 결정 2건이 착수하며 확정됐다**

- **DR-15** — ★ **vendor는 원본 크레이트 이름을 유지한다**(`nbeep-gfx`·`nbeep-ctl`). 이름을 바꾸면 vendor 내부 `use`를 고쳐야 해 **U-1이 성립하지 않는다**. 워크스페이스가 경로만 잡아 주면 **한 글자도 안 고치고** 컴파일된다.
- **DR-16** — i18n을 `nclip-core`에 beep와 **동형으로** 배치(`Lang`/`Msg`/`tr`/`current_lang`) → 이식 코드는 `use` 경로만 바뀐다.

**U-1을 문서에서 검증으로 옮겼다** — `crates/vendor/VENDOR.lock`(sha256 32개 + 출처 리비전) + `tools/check-vendor.py` + CI 게이트. 규칙을 문서에만 두면 언젠가 깨진다.

**아이콘** — 계열 골격(풀블리드 라운드 스퀘어·그라디언트·흰 전경·accent 모티프)은 유지하고 **클립보드 + 히스토리 스택**으로 특징을 냈다. 색은 **청록**(beep 파랑 / dir2 초록과 구분).

**다음** — ★ **T-9b(K-1 스파이크: 포커스 복원 + 키 주입)** 와 **T-12d(설정 화면 이식)**. 전자는 제품의 존재 이유가 걸려 있고, 후자는 3단계에서 "설정이 열리는 앱"이 된다.
