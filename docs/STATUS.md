## 2026-08-25 (3차) — beep UI 재사용 계획 확정

**한 줄**: 사용자 방침(*"beep의 골격과 설정화면을 되도록 그대로 써서 빠르게"*)을 **실코드로 검증**했다 — ★ **재사용 가능 ≈ 21,600 LOC**.

| 실측 근거 | 내용 |
|---|---|
| `nbeep-ctl/Cargo.toml` | ★ **의존이 `nbeep-gfx` 하나뿐** — *"앱 도메인 의존 금지가 이 크레이트의 존재 이유"* 라고 주석에 명시. **11,214 LOC 무수정 이식 가능** |
| `settings.rs` 헤더 | ★ **`Entry` 레지스트리 단일 원천** — 렌더·검색이 같은 원천을 읽는다. **`registry()`만 교체하면 3,510 LOC가 그대로 산다** |
| `controls/pulldown.rs:56` · `toolbar.rs:129` · `tree.rs:502` | ★ **`MenuBar`·`Toolbar`·`TreeGrid`가 이미 있다** → [DR-12](10-decision-record.md) 메인창이 기존 컨트롤로 조립된다 |
| `nbeep-plat/clipboard.rs`(550) · `tray.rs`(1,076) | 클립보드 어댑터·3-OS 트레이 이식 대상 |

**바뀐 판단**: `nexa-dir2` `grid`/`columns` 이식이 **불필요**해졌다(beep `TreeGrid`가 덮는다) → D-36.

**새 규율(U-1)**: ★ **복사한 파일은 고치지 않는다.** 확장은 우리 크레이트에서만 — *"복사해 놓고 조금씩 고치기"* 가 가장 나쁜 결말이라 **파일 단위로 경계를 강제**한다.

**착수 순서가 바뀌었다** — UI를 먼저 세워 눈에 보이게 하고 `plat`을 나중에: 복사 → i18n → ★ **설정 화면**(3단계에서 이미 "설정이 열리는 앱") → 트레이 → 도메인 → **클립보드 감시**(최대 난관) → 메인창 → 퀵 팝업 → **전역 단축키·키 주입**.
