| **DP-4** | ★ **beep UI를 최대한 그대로 쓴다** — `nbeep-ctl`·`nbeep-gfx` **무수정 복사**, `settings.rs`는 **`registry()`만 교체**. 확장은 우리 크레이트에서만(U-1) | [13](13-ui-reuse-from-beep.md) — 실측 재사용 **≈21,600 LOC** |

### DR-32 — `nexa-conf`는 이름을 바꾸지 않는다 (08-26)

[DR-17](#)이 `nbeep-*`를 `nclip-*`로 흡수한 것은 그 이름들이 **beep 전용**이었기 때문이다.
`nexa-conf`는 다르다 — **도메인 타입 0 · 시계 비소유 · 경로 비소유 · UI 비의존**이라
앱 이름이 들어갈 자리가 없다. `nexa-`는 계열 접두사지 앱 이름이 아니다.

★ [DR-18](#)이 말한 *"다음엔 라이브러리를 먼저 뽑자"* 의 **첫 후보**라, `nexa-beep`의 사본과
**본문을 같게 유지한다** — 공용 저장소로 옮길 때 diff가 아니라 **이동**이 되게. 고치는 것은 모듈 헤더뿐.

### DR-33 — 설정 저장 위치는 **포터블 우선** (08-26)

`실행 파일 옆 data/` → `사용자 설정 폴더` → `현재 폴더` 순.
★ **업그레이드 때 폴더째 교체되는 자리는 건너뛴다**(mac `.app` 번들 · Homebrew keg) —
**쓰기가 되는데도** 업그레이드가 디렉터리를 갈아 끼워 설정이 사라진다. beep이 실제로 겪은 사고다.

### DR-34 — hover는 **1000ms 동안 서서히** 밝아진다 (08-26 · 사용자 확정)

스플리터에서 시작해 hover 전체로 확장했다(*"Hover 에 대해서도 스플리터처럼"*).
Material의 상태 전이 90ms보다 11배 길다 — **의도된 예외**다.

| | 왜 |
|---|---|
| **느리게 들어온다(1000ms)** | hover는 *"여기 뭔가 있다"* 를 **조용히** 알리는 신호다. 90ms로 번쩍이면 마우스가 지나가기만 해도 화면이 소란스럽다 |
| **빠르게 나간다(220ms)** | 나가는 쪽까지 느리면 **잔상**이 남아 *"아직 거기 있나?"* 로 읽힌다 |
| ⚠️ **눌림은 예외** | 누른 것은 **즉시** 보여야 한다 — 페이드를 쓰지 않는다 |

구현은 [`nclip_ctl::tokens::Fade`] 하나로 모았다. ★ **hover는 배타적**이라 항목이 1,000개여도
움직이는 상태는 **둘뿐**이다([`HoverFade`]).

### DR-35 — 붙여넣기 모드는 **설정이 아니라 단축키**다 (08-26 · 사용자 확정)

> *"옵션이 아니면 단축키를 추가해서 선택할 수 있도록 하는 방법도 괜찮은 것 같아. Plain text로 붙여넣기랑 비슷하게 **객체로 붙여넣기** 단축키를 지정하게 하는 방법이지."*

| 모드 | 키 | 남기는 표현 |
|---|---|---|
| 원본 | `Enter` | 전부 |
| 평문 | `⇧Enter` | 평문 하나 |
| ★ **객체로** | `⌘/Ctrl+Enter` | 파일·개체만 |
| ★ **경로만** | `⌥/Alt+Enter` | 경로 텍스트만 |

★ **네 모드가 전부 같은 기계다 — "고르는" 게 아니라 "빼는" 것.**
대상 앱을 **탐지하지 않는다**. 올리는 표현을 좁혀서 앱이 고를 수밖에 없게 만든다.
앱 이름 목록을 유지할 필요가 없고, 원격 데스크톱·VM·Electron에서도 어긋나지 않는다.

**설정으로 두지 않는 이유**

| | |
|---|---|
| ⚠️ | 붙여넣기 **전에** 대상 앱을 예상해 미리 바꿔 둬야 한다 — 순서가 거꾸로다 |
| ⚠️ | 한 번 바꾸면 다음번에도 그대로 — **잊어버린 설정이 사고를 만든다** |
| ⚠️ | 앱별 규칙은 **영원히 늙는다** |

**단일 원천**: [`PasteAs::applicable(kind)`] — 힌트 줄·우클릭 메뉴·키 처리가 같은 답을 쓴다.
⚠️ 이미지 항목에 *"경로만"* 을 띄우는 것은 **거짓말**이라 테스트로 막았다.

⚠️ **모드는 요청이지 보증이 아니다** — 원격 파일이 용량 상한을 넘으면 `객체로`를 요청해도
경로만 나간다([26 §4-4](26-file-content-sharing.md)). ★ 사용자의 의사보다
*"실패할 약속을 하지 않는다"* 가 먼저다.

### DR-36 — 브라우저 암호 차단은 **옵션 · 기본 꺼짐** (08-27 · 사용자 확정)

> *"엣지의 암호 관리자에서 복사하면 클립보드에 남고 있음. 이 기능을 끄는건 기본은 꺼짐상태로
> 사용하지만 사용자가 켤 수 있도록 옵션 처리 해줘"*

08-27 실기에서 **Edge/Chrome 암호 관리자는 민감 표식을 붙이지 않는다**는 사실이 확인됐다
([27 §9 D-79](27-capture-cases.md)). 표식 존중(FR-S-1)의 구멍을 **출처 URL 휴리스틱**으로 메운다:

| | |
|---|---|
| 판정 | `Chromium internal source URL` 표현의 **내용**이 `edge://wallet/`·`chrome://password-manager/` 등 내장 암호 관리자 페이지면 민감([`is_password_manager_url`]) |
| 설정 | `sec.conceal_browser_pw` (보안·개인정보 · Toggle) — ★ **기본 꺼짐 · 옵트인** |
| 한계 | ⚠️ 브라우저 내부 URL 목록은 **버전에 따라 늙는다**(D-75와 같은 운영 — 실기에서 만나면 추가). 표식(`sec.respect_marks`)과 달리 **추정**이므로 기본을 끄는 게 정직하다 |

⚠️ 웹사이트는 이 판정을 **흉내 낼 수 없다** — `edge://`/`chrome://` 스킴은 브라우저 내부 페이지에서만 나온다.

### DR-37 — 저장 구조 = 자체 직렬화 · 인덱스/blob 분리 (08-31 · 사용자 확정 → D-1 닫힘)

[06 §5](06-storage-design.md#5-결정-d-1-답--확정-대기)의 권장안 D-1-a~f 전부:

| | |
|---|---|
| a | **자체 파일 직렬화** — SQLite 등 DB 엔진 링크 없음(DR-8) |
| b | **인덱스(작음·메모리 상주) / blob(큼·내용 주소 파일)** 분리 |
| c | 인덱스 = **append-only 암호화 세그먼트 + manifest**(beep `nbeep-store` 이식) |
| d | `blob_id = H(암호문)` — 중복 제거와 동기화([05](05-multi-device-sharing.md))가 같은 식별자 |
| e | 기본 상한 1만 항목까지 열어 두되 기본값은 DR-40(1000) |
| f | ★ 저장 계층은 **트레이트 뒤** — 틀렸을 때 되돌리기 위한 보험 |

→ **T-16 착수 가능.** ADR 승격 대상(T-7).

### DR-38 — at-rest 암호화 **기본 켜짐** · 꺼도 기기 키 암호화 유지 (08-31 · 사용자 확정 → D-9·D-74 닫힘)

⚠️ **[DR-20](#1-확정-결정-dr)(08-26 "로컬 암호화 = 선택 · 기본 끔")의 로컬 조항을 대체한다** — 08-31 재확정.
네트워크 ≫ 로컬 우선순위 자체는 유지된다.

| | |
|---|---|
| 기본값 | `sec.encrypt_at_rest = on` — 제품 차별점 ②("암호화가 기본값") 정합 |
| off의 의미 | **D-74 = (b)** — 기기 로컬 키로는 항상 암호화 · 패스프레이즈만 안 받음. 완전 평문(a)은 없다(무결성 검증까지 잃는다) |
| DR-20과의 공존 | (b) 덕에 꺼도 사용자 부담 0 + 파일 뒤짐·백업 유출 방어는 남는다 |

### DR-39 — 신원·페어링 = 핸들+패스프레이즈 · 3분 창 · 느슨 승인 (08-31 · 사용자 확정 → D-24~29 닫힘)

[09 §10](09-identity-and-pairing.md#10-열린-결정) 권장안 일괄:
**D-24** 랑데부 파생 = 핸들+패스프레이즈 · **D-25** 페어링은 명시적으로 연 3분 창 동안만 ·
**D-26** 승인 = 느슨(아무 기기 + 전 기기 알림 + 거부권) · **D-27** 6자리 숫자 기본(모바일 QR) ·
**D-28** KDF = PBKDF2-HMAC-SHA256 자체 구현(DR-8) · **D-29** 강도 표시 + 약하면 경고(강제 없음).
→ ADR-0007 실구현(T-24)의 입력. ADR 승격 대상(T-7).

### DR-40 — 수식 키 Maccy 방식 · 검색 모드 二원 · 기본 보관 1000 (08-31 · 사용자 확정 → D-38~40 닫힘)

**D-38** 수식 키 = Maccy 방식(Enter 기본 + `⌥`/`⇧` 즉석 변형 — 설정을 덜 건드린다 · T-15b 입력) ·
**D-39** 검색 모드 = 설정 택일 + 검색바 토글 **둘 다** · **D-40** 기본 보관 = **1000**(현 기본값 유지 · 인덱스 ~0.3MB).
