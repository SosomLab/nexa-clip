# 30 · 메모리 상주 계층 — 메타만 남기고 비우기 · 쓸 때 다시 채우기 (설계 · 2026-09-04)

> 사용자 요청(09-04): *"메모리 사용량이 많다. 순위가 밀려 당분간 안 쓸 항목은 **메타만 남기고 해제**하고, 쓸 때 다시 로딩하는
> **주기적 최적화 스케줄**을 넣고 싶다."* — [DR-41 최소 처리 원칙](10-decision-record.md)의 메모리판.
> 관련: [06 저장 설계](06-storage-design.md) · 09-03 11차 blob 지연 로드(287→21MB) · [DR-9 예산 게이트](10-decision-record.md).

## 1. 실측 (09-04 · Windows · 291개 항목 · 디버그 빌드)

| 항목 | 값 |
| --- | --- |
| Working Set / Private / Peak | **82MB / 65MB / 125MB** |
| 저장소 `index` (디스크) | **64MB** — 항목 메타 + ★ **섬네일 원시 RGBA**(512² 최대 1MB/장)가 여기 들어 있어 **기동 때 전부 적재**된다 |
| 저장소 `blob` (디스크) | 447MB — 본문(표현 바이트). 09-03부터 **지연 로드**(`blob_refs` → `ensure_loaded`) |

09-03 지연 로드 직후 21MB였던 RSS가 82MB인 이유는 셋이다.

1. **섬네일이 인덱스에 원시 RGBA로** 있어 291개분(스크린샷이 많다)이 기동 때 통째로 올라온다 — 64MB의 대부분.
2. `ensure_loaded`로 채운 **본문은 한 번 올라오면 내려가지 않는다**(복사·미리보기·이미지로 복사 때마다 누적).
3. 메인창·팝업의 `Row`가 **섬네일 RGBA를 복제**해 `IconImage`로 든다(창이 열려 있으면 항목당 최대 2벌 추가) · 리치 런은 **모든 행**을 매 `refresh`마다 400줄까지 파싱한다.

## 2. 상주 계층 (residency tiers)

| 계층 | 내용 | 크기(항목당) | 정책 |
| --- | --- | --- | --- |
| **M 메타** | id · kind · label · 출처 · copies · pinned · created · 내용 열쇠 · `blob_refs` · 원본 치수 | 수백 B | **항상** 상주(검색·목록·중복 판정은 이걸로 끝난다) |
| **T 섬네일** | 목록용 축소 이미지 | 512² RGBA ≤ 1MB (PNG면 30~100KB) | **온**(warm) — 화면 근처 것만 상주, 나머지는 비운다 · 쓸 때 다시 |
| **B 본문** | `reps[].data` | 수 KB ~ 수 MB | **냉**(cold) — 쓸 때 채우고(기존) ★ **쓰고 나면 비운다**(신설) |
| **V 뷰 캐시** | `Row.thumb` 복제 · 리치 런 · 미리보기 디코드 이미지 | 항목당 T·B와 같은 규모 | 창 열린 동안만 · 보이는 행만 · 복제 대신 **공유**(`Rc`) |

"메타만 남기고 해제"란 T·B·V를 내리고 M만 두는 것이다. M은 지금도 전부 메모리에 있고(1만 건 ≈ 3MB · 06 §표) 그대로 둔다.

## 3. 무엇을 언제 비우나 — 순위와 스케줄

**순위** = 이력 순서(최근 승격 순)가 곧 "다시 쓸 확률"이다. 고정(pinned)은 축출에서 보호되는 것이지 자주 쓰는 것이 아니므로 **순위에 특혜를 주지 않는다**(결정 ①).

| 트리거 | 하는 일 | 비용 |
| --- | --- | --- |
| **GC 틱**(주기 · 결정 ③) | 순위 > `WARM_BODIES`(본문) / > `WARM_THUMBS`(섬네일)인 항목의 B/T를 `Vec` drop — 예외: 현재 선택·미리보기 중·최근 `USE_TTL` 안에 쓴 항목 | 드롭뿐 · μs |
| **사용 직후** | 복사·이미지로 복사·전파로 채운 본문은 **쓰고 나면 즉시 비운다**(다음 사용은 다시 읽는다 — 결정 ②) | 0 |
| **창 닫힘** | 메인/팝업 `rows` 비움(V 전부) — 지금은 닫아도 남는다 | 0 |
| **예산 초과**(결정 ④) | 추정 상주 바이트(M+T+B+V 합산 카운터)가 예산을 넘으면 GC 틱을 기다리지 않고 순위 낮은 쪽부터 비운다 | 드롭뿐 |

GC 틱은 셸 `about_to_wait` 박동(500ms)에 얹되 **유휴 조건**(마지막 입력·캡처 뒤 5초)에서만 돈다. 비우기는 전부 `Vec` drop이라 **한 틱에 전부 해도** UI를 막지 않는다(제한 개수 점진은 **다시 채우기** 쪽에만 필요).

## 4. 다시 채우기 — 프로세스가 기다리지 않게

| 대상 | 방식 |
| --- | --- |
| 본문(B) | 지금처럼 **동기**(`ensure_loaded` — 복사 직전 blob 1개 복호 · 수 ms). 사용자 행위 직후라 체감 없음 |
| 섬네일(T) | ★ **비동기** — 스크롤로 화면에 들어온 행의 T가 없으면 워커에 요청(`ShellEvent::ThumbReady(id)`), 올 때까지 자리표시(치수는 M에 있으니 행 높이는 흔들리지 않는다). **의도 코얼레싱**([28 §hover](28-main-window.md)) 그대로: 빠르게 지나간 행은 요청조차 안 한다(70ms · 스크롤 안정 120ms) · 동시 요청 ≤ 4 · 뷰포트 ± 1화면만 |
| 리치 런(V) | 행이 **보일 때** 파싱해 캐시(`Row.rich = OnceCell`) · `refresh`에서 전 행 파싱 중단 |
| `Row.thumb` | 복제 대신 `Rc<IconImage>` 공유(메인·팝업·미리보기가 한 벌) |

## 5. 섬네일 저장 형식 — 결정 ⑤ (가장 큰 효과)

지금 인덱스에 **원시 RGBA**로 있어 (a) 인덱스가 64MB로 부풀고 (b) 기동 때 전부 적재된다. 선택지:

| 안 | 내용 | 효과 | 비용 |
| --- | --- | --- | --- |
| **A. PNG blob 이관(권장)** | 섬네일을 **PNG로 인코드**(격리 워커 · 이미 있음)해 `blob`에 두고 인덱스엔 참조만 | 인덱스 64MB → ~1MB · 기동 적재 0 · 디스크 -55MB 이상 | 표시 때 디코드(워커 · 512² PNG 5~15ms) — §4 비동기로 흡수. 기존 인덱스 **마이그레이션 1회**(기동 때 순차 이관 · 제한 개수 점진) |
| B. 원시 유지 + 축출만 | 인덱스는 그대로, 메모리에서만 순위 밖 T를 비우고 필요할 때 인덱스 재독 | RSS는 준다 · 디스크·기동은 그대로 | 인덱스 재독 = 세그먼트 재파싱(수십 ms) — 비동기 필수 |
| C. 해상도 축소(512→256) | 장당 1MB → 256KB | 즉시 ¼ | 200px 표시 상한이라 시각 차이 작음 · **A와 병행 가능** |

## 6. 결정이 필요한 것 (사용자)

| # | 질문 | 권장 |
| --- | --- | --- |
| ① | 고정 항목도 순위대로 비우나(쓸 때 다시 채움) · 아니면 항상 상주? | 순위대로(고정 = 축출 보호이지 상주 보증이 아니다) |
| ② | 본문은 **쓰고 나면 즉시** 비우나, GC 틱까지 두나? | 즉시(복사 뒤 같은 항목을 곧 다시 쓰는 일은 드물고, 다시 읽어도 수 ms) |
| ③ | GC 틱 주기 · 온(warm) 개수 | 유휴 5초 뒤 30초마다 · 본문 0개(= 즉시 비움) · 섬네일 = 뷰포트 ± 1화면 + 최근 사용 10분 |
| ④ | 상주 예산 수치(DR-9 "미정") | **유휴 40MB · 활동 중 상한 96MB**(넘으면 즉시 GC) — 실측으로 조정 |
| ⑤ | 섬네일 저장 = A(PNG blob 이관) / B / C / A+C | **A + C(384²)** — 인덱스 60MB↓ · 기동 즉시 · RSS는 화면에 보이는 만큼만 |

⑤가 가장 큰 효과이면서 **저장 형식(마이그레이션)을 건드리는 결정**이라 먼저 확정이 필요하다. ①~④는 상수라 나중에 바꿔도 된다.

## 7. 구현 순서(결정 뒤)

1. **V 정리**(결정 불요 · 바로): `Row.thumb` 공유 · 리치 런 지연 파싱 · 창 닫힘에 rows 비움. → 창 열린 동안 -30~50%.
2. **B 즉시 비움 + GC 틱**(①②③④): `HistoryItem::unload()`(`reps[].data` → `blob_refs` 복원 — 저장 형식 변경 없음 · 이미 참조를 들고 있다) + 상주 바이트 카운터 + 유휴 틱.
3. **T 이관·비동기 채움**(⑤): 저장소 `thumb_blob` + 마이그레이션 + 워커 디코드 + 자리표시.
4. 검증: 기동 RSS · 유휴 30분 RSS · 스크롤 1000행 왕복 RSS·프레임 · 복사 지연 — [21](21-manual-test.md) 항목 추가 · DR-9 게이트 수치 확정.
