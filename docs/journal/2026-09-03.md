## 3차 — 실기 판정: "터미널에 붙여넣기 안 됨" = 결함 아님 — VTE Ctrl+V 관례

사용자 실기(B1 변형 — 대상 = 터미널): 팝업 선택 → 로그 `재적재 … 표현 4개 게시` · `붙여넣기: 포커스 복원 + 키 주입 ok`,
그러나 터미널에 안 붙음.

**교차 실증**: `peek`(내재 읽기)로 회수 — 재적재 항목이 4개 표현 그대로 서빙 중 ✓. 즉 수집→재적재(내재 서빙)→주입까지
전부 정상이고, **GNOME 터미널(VTE)이 Ctrl+V를 붙여넣기로 받지 않는 것**(터미널 관례 = Ctrl+Shift+V · Ctrl+V는 리터럴)이 원인.
Windows 터미널은 Ctrl+V를 받으므로 Windows 동등성 결함도 아니다.

- 즉시 우회: 터미널에서는 선택 후 **Ctrl+Shift+V 수동**(클립보드엔 이미 실려 있다)
- 본편 방향(신규 T-15c): **대상 앱별 주입 조합** — X11/XWayland 창은 `WM_CLASS`로 터미널 감지 가능 ·
  네이티브 Wayland 창은 포털이 대상 정체를 안 주므로 **감지 불가 판정**(정직 강등 · 문서 안내)
- 부수: `scripts/dev-restart.sh` 신설(빌드→종료→재시작 · `--diag`) — 사용자 요청
