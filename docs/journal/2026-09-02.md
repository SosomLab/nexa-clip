## 14차 — 표시 배율 = 문서 논리 크기(CopyQ 기준 차용)

픽셀 분석 — PPT 래스터(PNG/DIB)는 ~150dpi 렌더라 화소 수 그대로는 실물보다 ~1.56배 크다.
CopyQ는 SVG **선언 크기**(447×51)로 그려 실물과 유사 → 표시 치수 우선순위를
**SVG width/height → EMF 프레임(0.01mm→96dpi) → 라벨 W×H(폴백)** 로 교체(`display_dims`).

## 12차 — ★ 근인 확정: 단일 섬네일 후보 포기 → 캐스케이드

"왜 아직도 평문으로 보이나" — store_dump 실측으로 근인 확정: PPT 글상자 항목(id 135~141)은
**PNG(2.2KB)·CF_DIB(91KB)·EMF(5.4KB)를 전부 들고 있는데 `thumb=-`** — 재료 선택이 1순위(PNG)
하나만 시도하고 실패하면 포기했다(PPT PNG는 워커가 못 읽는다 — 이유 불문으로 DIB가 멀쩡).

→ `thumbnail_sources()`(순위순 전체) + `decode_image` 캐스케이드(성공할 때까지) —
PNG 실패 → DIBV5 → DIB → EMF. 기존 항목도 미리보기 패널(지연 디코드)은 즉시 혜택,
목록 섬네일은 재복사 시 생성.

**CopyQ 방식 분석**(사용자 질문): Qt 위젯 — 보관한 표현 중 하나를 Qt가 그린다.
text/html은 QTextDocument(서식 글자 조판), image/svg는 QtSvg(벡터 — 확대해도 선명),
PNG 등은 QPixmap. PPT 글상자는 **텍스트 조판이 아니라 이미지(SVG/PNG) 렌더**다.
우리는 같은 재료를 DIB/EMF 경로로 래스터화해 그린다 — 구조적으로 동등.

## 10차 — ★ EMF 래스터화: PPT 글상자가 **서식 그대로** 보인다

사용자 — "글상자 복사한 모양이 Ctrl+1에서 바로 보였으면 · Rich Text로 안 보임". PPT는 래스터
표현 없이 EMF·SVG만 준다 → **EMF를 Windows GDI가 직접 그린다**(파서 링크 0 · DR-8 부합).

| 단계 | 내용 |
|---|---|
| 캡처 | `watch_win`: CF_ENHMETAFILE(14)만 예외로 `GetEnhMetaFileBits` 실바이트(상한 16MB) |
| 래스터 | 신설 `nclip-plat::emf` — SetEnhMetaFileBits → 헤더 프레임(0.01mm→96dpi) → DIB 섹션에 PlayEnhMetaFile → BGRA→RGBA. ★ 벡터라 짧은 변 ≥96px 보정(와가로 글상자 선명) · 총화소 4M 상한 |
| 연결 | `thumbnail_source`: 항상 빈 핸들인 CF_BITMAP 제외(★ PPT에서 EMF를 가리던 원인) · EMF 최후순(4) · `decode_image`에 Windows 분기 |
| 실측 | probe: 빨강 볼드 텍스트 EMF 1.2KB → 884×96 · 비백색 9,872화소(텍스트 렌더 확인) |

⚠️ **지켜볼 것**: EMF 바이트가 동일성 판정(fingerprint)에 들어간다 — PPT 연타 복사에서 ×n이
안 무는 현상이 재발하면 EMF를 휘발 목록 검토. mac 대응물(PDF 표현)은 후속.

**게이트**: clippy 3타깃 · 테스트 전부 통과(계약 테스트 갱신) · debug exe 갱신.
