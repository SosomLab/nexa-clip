## 4차 — 남은 Linux 확인 사항 소화: X11 경로 · 다른 컴포지터 · 프로토콜 실측

사용자 요청 — *"리눅스에서 확인해야 할 사항 진행. 기능 개발은 mac에서."* 3차가 남긴
⏳ 넷(X11 · 파일 관리자 · 다른 컴포지터 · data-control 버전) 중 **이 PC에서 사람 없이 되는 것**을 했다.
전부 **sudo 없이** — 3차의 `apt-get download` + `dpkg-deb -x` 방식 그대로(`xvfb`·`wayland-utils`·`weston`).

### X11(`xclip`) 경로 — X11 세션 로그인 없이 두 방법으로

| 방법 | 원리 | 결과 |
|---|---|---|
| **XWayland** | `WAYLAND_DISPLAY`만 지우면 `pick_backend`가 `DISPLAY=:0`으로 간다. Mutter가 X↔Wayland 클립보드를 **양방향**으로 잇는다 | ✅ `x11-xclip` **7/7** |
| **순수 Xvfb** `:99` | X 서버만 따로 — 데스크톱 클립보드와 무관 | ✅ **7/7** + 표식 `peek` 거부 |

하네스에 `NCLIP_E2E_X11=1`(+`NCLIP_E2E_XVFB=1`) 모드를 더했다 — 주입만 `wl-copy`↔`xclip -t`로
갈아 끼우는 `put` 하나. ★ XWayland 실행에서는 **직전 Wayland 실행의 케이스 8(표식)을 X11 백엔드가
기동 시 `[지금 클립보드] (민감 표식)`으로 거부**했다 — 브리지 너머로도 fail-closed가 선다.

### 다른 컴포지터 — Weston 14.0.2 nested

- headless 백엔드는 **seat가 없어 wl-clipboard가 거부**한다(*"does not seem to implement seat"*) →
  wayland 백엔드(nested · pixman)로 seat를 빌려 실행. 텍스트·HTML·`gnome-copied-files` 정판정 ✅.
- `WESTON_MODULE_MAP`으로 모듈 경로를 지정해야 로컬 프리픽스에서 돈다(컴파일된 경로가 `/usr/lib`).

### ★ 프로토콜 실측 — [docs/18 §9-5](../18-build-and-test.md) 표가 "문서 기반"에서 "측정"이 됐다

`wayland-info` — **Mutter 50.1**(Ubuntu 26.04)과 **Weston 14.0.2** 모두 `wl_data_device_manager v3`뿐,
`zwlr_data_control`·`ext_data_control_v1` **둘 다 없다**. 1단이 도구 파이프인 근거가 이 PC에서
수치로 확인됐다. KWin·wlroots는 이 PC에 없어 여전히 문서 기반(표시해 둠).

### 결함 하나 — Linux에서 거짓인 안내

빈 클립보드에서 `peek`가 *"클립보드를 열지 못했습니다(**다른 앱이 잡고 있을 수 있습니다**)"* —
Windows `OpenClipboard` 사정이다. Linux는 잠금이 없고, `wl-paste --list-types`·`xclip -t TARGETS`는
**비어 있음과 못 읽음을 같은 비정상 종료로** 돌려준다(3차 결함 ②와 같은 뿌리). 로그인 직후가
정확히 이 상태라 첫인상이 거짓이 된다 → `read_failed_hint()` — Linux는 *"비어 있거나 읽지 못했습니다
(도구 파이프는 둘을 구분하지 못합니다)"*, 다른 OS는 종전 문구. stderr 텍스트로 둘을 가르는 건 취약해 안 했다.

### 관찰(수정 없음)

- `xclip`은 `wl-copy`와 달리 **`text/plain`을 덧붙이지 않는다** → HTML/RTF 단독 주입이 `미리보기 없음`.
  실제 앱은 평문을 함께 내놓으므로 하네스 성질이다. 다만 **평문 없는 RichText의 미리보기**는 T-18d(렌더러)에서 채울 자리.
- ⚠️ 클리피 `items_after_test_module` — 헬퍼를 파일 끝에 붙였다가 걸렸다. **테스트 모듈 위**에 둔다.

### ✅ Nautilus 실제 표현 — 사용자 실기(`Ctrl+C` · `Ctrl+X`)

둘 다 `Files` · 파일명 정확. 표현 5개: `text/uri-list` · `text/plain;charset=utf-8` ·

- **Klipper·GPaste 공존**.

## 3차 — Linux 실기 환경 구축 + 실기가 잡은 결함 여섯

**사용자 요청 셋** — ① *"저장소 최신화 및 변경사항 분석"* ② *"전체 테스트를 자동화, 파일 포함"*
③ *"빌드/테스트 환경 모두 구성 + 리눅스 환경 문서, 배포판별 차이 포함"*.

이 자리가 **Linux 데스크톱**(Ubuntu 26.04 · GNOME/Wayland)이라 1차에서 못 한 Linux 실기를
여기서 했다 — 그리고 **실기가 결함 여섯을 잡았다**. 자동 하네스가 값을 했다.

### 환경 — ★ sudo 없이 구성했다

이 PC에는 **Rust 툴체인도 C 컴파일러도 없었다**. `sudo`는 암호가 필요해 쓸 수 없었다.

- rustup → stable 1.98.0 + rustfmt·clippy + 5타깃(사용자 홈, sudo 불요).
- ★ **`cc`가 없어 아무것도 안 됐다** — `cargo test`는 물론 **크로스 `cargo check`도** 죽는다
  (`libc`·`proc-macro2`·`crossbeam-utils`의 **빌드 스크립트가 호스트에서 링크**된다).
  링커 없이 되는 건 `cargo fmt` 뿐이었다.
  ⚠️ [docs/18 §1](../18-build-and-test.md)이 *"외부 도구 없음 · C 툴체인 불요"* 라고 적고 있었다 — **정정했다**.
- 루트 없이: `apt-get download`(root 불요) + `dpkg-deb -x` → `~/.local/nclip-devenv`.
  함정 하나 — gcc 드라이버가 `cc1`을 **자기 위치 기준**으로 찾는데 `cpp-15`만 시스템에 있어
  경로가 어긋났다. 시스템 `cc1`을 로컬 프리픽스에 심링크해 해결.
- ⚠️ 사용자 질문 *"vscode를 sudo로?"* → **아니다.** 세션 전체가 root가 되어 `target/`·`~/.cargo`·
  저장소 파일이 root 소유로 바뀐다. 절차를 [docs/18 §9-3](../18-build-and-test.md)에 남겼다.

### 실기 — [`scripts/linux-watch-e2e.sh`](../../scripts/linux-watch-e2e.sh) 8유형 자동화

Windows·macOS는 사람이 앱에서 복사해 눈으로 봤지만, Linux는 `wl-copy --type`으로
클립보드에 유형을 직접 쓸 수 있다 — **사람 없이 재현되는 하네스**를 만들었다.

★ 하네스 자체에서도 둘을 데었다(스크립트 주석에 박제): ① watch의 stdout이 파일이면
**블록 버퍼링**이라 종료 시 꼬리가 유실된다(`stdbuf -oL`) ② 케이스 마커를 감시 로그에
덧붙이면 두 writer의 오프셋이 충돌해 로그가 깨진다(파일 분리).

### ⑥ 부분 스냅숏 — 폴링만의 함정

`text/html` 복사가 `text/plain` 하나만 보이는 순간에 잡혀 **같은 복사가 두 항목**이 됐고,
먼저 것은 표현이 모자라 **`Text`로 오분류**됐다.

- 수신 루프의 디바운스(D-80 · 500ms)가 원래 이걸 합치는 자리인데,
  **Linux 폴링 주기가 500ms라 완본이 창 밖에 떨어진다** → 백엔드가 먼저 다잡는다(`settle`).
- ⚠️ 처음엔 [`coalesces`](../../crates/nclip-core/src/capture.rs)로 판정했는데 **절반만 막혔다** —
  그건 표현이 **늘어나는** 방향(부분 ⊆ 완본)만 합친다. 실기에는 **줄어드는** 전이도 있었다
  (`{text/plain, gnome-copied-files}` → `{gnome-copied-files}`). 규칙을 **"두 번 같게 읽힐 때까지"**
  하나로 바꿔 둘 다 막았다(120ms × 최대 4회).
- ★ **480ms 안의 두 번째 복사를 잃지 않는다** — 폴링 주기가 이미 500ms라 그보다 짧게
  스쳐 간 복사는 애초에 보이지 않는다. 자리 잡기는 폴링이 줄 수 있는 것을 깎지 않는다.

## 2차 — 사용자 실기(mac 유형별 훑기)가 결함 둘을 잡았다

사용자가 `watch`로 유형별 훑기(터미널 텍스트·리치·PNG·★ **PPT 도형**·파일 3건) —
판정 자체는 전부 정확했다(PPT 도형 = `Object` 12표현 · GVML/SVG/PDF/TIFF까지 —
Windows 결함 ⑤의 `ClipKind::Object`가 mac에서도 그대로 값을 했다). 결함 둘:

### ① 한글 파일명이 자모로 낱낱이 보였다 — macOS는 NFD를 준다

`한글.pdf`가 `한글.pdf`(첫가끝 자모)로 — **macOS 파일명·파일 URL은 NFD(분해형)**다.
퍼센트 디코딩은 바이트 정확(손실 없음)이고, 문제는 표시 층: 우리 래스터라이저는
자모 결합(shaping)을 안 하므로 제품 화면에서도 낱자로 보일 실결함. 검색도
NFC(IME 입력)와 안 맞는다.

- ★ [`capture::compose_hangul_nfd`](../../crates/nclip-core/src/capture.rs) —
  유니코드 표준 조합(L·V·T → `0xAC00 + L×588 + V×28 + T`) **한글 한정 NFC**.
  범위 밖(옛한글·라틴 결합 부호)은 그대로(지어내지 않는다) · NFC 입력엔 멱등이라
  **3-OS 공통**으로 건다. 적용은 `file_names()`(표시)만 — **경로는 원본 유지**.
- ⚠️ beep `hangul.rs` 이식이 아니다 — 그쪽은 호환 자모(ㄱㅏ) **IME 조합기**(키 입력),
  이건 첫가끝 자모 **NFD 정규화**(표시). 층도 용도도 다르다.

### ② 출처 앱이 전부 iTerm2 — `NSWorkspace`는 런루프 없이 갱신되지 않는다

PPT·Finder 복사까지 **전부 iTerm2**로 찍혔다. `NSWorkspace.frontmostApplication`은
**메인 런루프가 도는 앱에서만** 갱신된다 — 감시 프로세스(터미널 명령)는 런루프가
없어 시작 시점 값이 박제됐다. 제외 앱 게이트(FR-S-2)가 이 값을 쓰므로 표시 문제가
아니라 **판정 문제**다.

- ★ `CGWindowListCopyWindowInfo`로 교체 — 부를 때마다 창 서버에 묻는다(런루프 불요).
  화면 z순서 첫 **layer 0 창**의 소유 앱(`kCGWindowOwnerName`) = 프런트모스트.
  창 이름과 달리 소유 앱·레이어는 **화면 기록 권한이 필요 없다**. 복사 이벤트당
  1회만 부른다(DR-9).
- ✅ 실기: Finder ⌘C → `출처: Finder` · `미리보기: 한글검증_v1.0.pdf` 둘 다 정상.

### 관찰(수정 없음 — 기록만)

- PPT 도형 재복사에서 `com.microsoft.ole.source.34028.0x…` 토큰이 **복사마다 다르다** —
  이력 동일성(정렬된 표현 전체)이 이런 휘발 표현 때문에 **승격 대신 새 항목**으로
  판정할 수 있다. Windows도 동일 소지. 이력 동일성에서 휘발 벤더 토큰 제외를
  검토할 것(T-13 후속).
- PPT가 앞에 있는 동안 `dataForType:`이 nil인 표현(`image-svg-xml (핸들)`)이
  있었다 — 지연 제공. 이름만 담는 현 처리로 분류엔 지장 없고, 다음 복사에선 실데이터가
  왔다. 의도된 동작.

**실측**: **337 테스트**(+NFC 3) · clippy 클린(호스트 + linux 크로스) · win-msvc check 클린.

## 1차 — T-14e macOS 감시 + Linux 감시 1단: 3-OS가 처음으로 다 잡는다

사용자 요청 둘("윈도우와 같이 유형별 복사/잘라내기 테스트, 파일 포함" · "리눅스에 필요한
기능도 함께")을 이 Mac에서 한 번에 진행 — 감시가 Windows뿐이라 **macOS 백엔드(T-14e)를
구현하고, Linux 1단도 함께** 만들었다. `watch`/`peek`/게이트/디바운스는 OS 중립이라
백엔드만 붙이면 그대로 돈다(포트 설계가 값을 했다).

### macOS — [`watch_mac`](../../crates/nclip-plat/src/watch_mac.rs) (`mac-changecount-poll`)

- **`changeCount` 적응형 폴링**([docs/20 §3-1] 사양 그대로) — 활동 200ms → 유휴 1s.
  변할 때만 내용을 읽는다(유휴 비용 = 1초당 objc 호출 1회 · DR-9).
- **objc 런타임 직접 호출** — `paste.rs` appkit 선례 재사용(DR-8 외부 crate 0).
  autorelease 풀을 읽기마다 짝 맞춰 닫는다(백그라운드 스레드 누수 방지).
- ★ **Windows 결함 ⑫의 교훈을 설계에 선반영** — 내용 없는 스냅숏은 **미처리**
  (번호를 안 올리고 재시도). 비우고→채우는 틈에 읽어도 유실이 없다.
- 민감 표식 = `org.nspasteboard.{Concealed,Transient,AutoGenerated}Type`
  ([docs/20 §297]) — **존재만으로** 금지 + 표식이 서면 **바이트를 읽지 않는다**(fail-closed).
- ★ **Finder는 경로가 아니라 참조 URL을 준다**(실기) — `file:///.file/id=…`가 그대로
  보이면 미리보기가 `id=…`가 된다 → `NSURL.filePathURL`로 **캡처 시점에 푼다**.
- 출처 앱 = `NSWorkspace.frontmostApplication` **근사**(파스텔보드에 주인 API가 없다 —
  Windows `GetClipboardOwner`와 다른 한계. 표시·제외 앱 판정용으로는 실용 충분).

**실기(유형별)** — 전부 이 Mac에서 확인:

| 유형 | 결과 |
|---|---|
| 텍스트(한글) | ✅ `public.utf8-plain-text` · 미리보기 정상 |
| RTF | ✅ `RichText` |
| PNG | ✅ `Image` + **치수 256×256**(T-14c `img`가 mac에서도 그대로) |
| ★ **Finder ⌘C 파일** | ✅ `Files` — 표현 4개(file-url·텍스트 2종·icns) · 참조 URL → **파일명 미리보기** |
| 파일 여러 개(Path Finder) | ✅ 다중 항목 평탄화 — 한글 파일명 정상 |

- ⚠️ **발견**: AppleScript `set the clipboard to (POSIX file …)` 는 changeCount를 안
  올리고 내용을 **늦게** 채운다 — 그 세대를 빈 것으로 본 프로세스는 캐시가 고정돼
  계속 빈 것으로 읽는다(신선한 프로세스는 읽힘 · diag로 해부). **실제 앱(Finder 등)은
  원자적으로 써서 무관**. 파스텔보드 수준 `types`/`dataForType:` 폴백은 넣어 뒀다.
- `NEXA_CLIP_DIAG=1` 진단을 mac 폴링 루프에도 배선(watch_win과 같은 규약).

### Linux — [`watch_linux`](../../crates/nclip-plat/src/watch_linux.rs) 1단 (`wayland-wl-paste` / `x11-xclip`)

- **도구 파이프**(beep `nbeep-plat/clipboard.rs` Linux 선례) — `wl-paste` → `xclip`
  사다리. 링크 의존 0 · 두 표시 서버 공통. XFIXES/data-control은 본편(T-14 본체)으로.
- **환경 판별을 능력으로** — 표시 서버 없음 = `NoDisplayServer` · 도구 없음 =
  `MissingTool`(**신설** — `UnsupportedReason`에 설치 대상 이름을 담는다) · 있으면 지원.
- 변화 감지 = **내용 지문**(FNV — Linux엔 일련번호가 없다) · 활동 500ms → 유휴 2s.
  빈 스냅숏 미처리 규칙 동일. 민감 표식 = `x-kde-passwordManagerHint`
  (값 `secret` — **못 읽으면 금지**로 fail-closed).
- 타깃 정규화 — `UTF8_STRING`·`STRING`·`TEXT`·`;charset=…` → `text/plain` 한
  이름으로(판정 어휘 · docs/12). 곁다리(`TARGETS`·`TIMESTAMP`…)는 읽지 않는다.
- ⚠️ 실기는 못 했다(이 자리에 Linux 실기 환경이 없다) — 순수부(정규화·지문·주기)는
  테스트로 박제, `x86_64-unknown-linux-gnu` 크로스 clippy `-D warnings` 클린.

### 배선 — [`watch.rs`](../../crates/nclip-plat/src/watch.rs)

- `capability`/`read_now`/`start`가 3-OS 분기. 게이트 랩은 한 벌(OS 밖 규칙 유지).
- "구현 없는 타깃" 테스트 둘 → **mac 백엔드명 검증 + Linux 정직 보고 검증**으로 교체
  (Linux는 이제 `NotImplemented`라고 말하면 안 된다).

**실측**: **334 테스트**(+mac 3 · linux 4) · clippy `-D warnings` 클린(호스트 +
linux-gnu 크로스) · Windows msvc `cargo check` 클린 · rustfmt 클린. 외부 crate 추가 0.
