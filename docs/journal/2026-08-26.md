## 5차 — 구현 설계서 ([20](20-implementation-spec.md))

사용자 요청: *"개략적인 화면의 레이아웃과 필요한 기능 목록, 각 기능의 구현 방법, 설정 화면의 구성 등에 대해서 정리해서 문서로."*

앞의 문서들이 **무엇을·왜**는 충분히 덮었는데 **어떻게**가 비어 있었다. 그래서 [20](20-implementation-spec.md)의 무게중심을 **§3 구현 방법**에 뒀고, 나머지 절은 요약 + 링크로 처리해 중복 서술을 피했다([16 §2-1](16-doc-git-conventions.md)).

**§3에서 실제로 채운 것** — 기능마다 `🆕`(신규) / `♻`(이식) / `⚠`(난관)을 표기해 **어디에 시간이 드는지**가 한눈에 보이게 했다.

- **클립보드 감시**: Win `AddClipboardFormatListener`→`WM_CLIPBOARDUPDATE`(숨은 메시지 창 — beep `tray.rs`의 전용 스레드 패턴 재사용) · mac `changeCount` **적응형 폴링**(포커스 200ms / 유휴 1~2s) · X11 `XFixesSelectSelectionInput` · Wayland `zwlr/ext-data-control`. `OpenClipboard` 실패는 **정상**(다른 앱 잠금)이라 짧은 백오프 재시도로 다뤄야 한다는 점을 명기.
- **다중 표현**: Win `EnumClipboardFormats`+`GetClipboardFormatNameW` / mac `NSPasteboard.types` / Linux `TARGETS`. ⚠️ **`CF_HTML` 오프셋 헤더**는 저장 시 벗기고 쓸 때 다시 씌운다.
- **전역 단축키**: mac은 `RegisterEventHotKey`(Carbon)를 고른 이유가 **권한 불필요**라는 점 — `CGEventTap`은 손쉬운 사용 권한을 요구한다. X11은 NumLock/CapsLock 변형까지 등록해야 한다.
- ⚠️ **포커스 복원 + 키 주입**: 6단계 흐름(단축키 → **띄우기 전** 포그라운드 기억 → 표시 → 숨김 → 재활성 → 주입)과 OS별 API를 표로 확정. Windows `SetForegroundWindow`의 **`AttachThreadInput` 트릭**, mac **손쉬운 사용 권한 필수**, **Wayland는 표준이 없어 강등**. 대안으로 Windows `WS_EX_NOACTIVATE`(애초에 포커스를 안 뺏는 창)를 스파이크 비교 대상으로 남겼다.
- **가변 행 높이 가상화**: 고정 높이는 `scroll_y / row_h`로 O(1)이지만, **일반 보기는 가변**이라 **높이 캐시 + 누적합 배열 + 이진 탐색**이 필요하다. 항목 추가는 꼬리만 갱신.
- **제한 리치텍스트 렌더러**: 태그·속성 화이트리스트, 스크립트·이벤트 핸들러·**외부 리소스 로드 금지**, 파싱 실패 = **평문 폴백(fail-closed)**. RTF는 1차에 굵기·기울임·색만.
- **민감 차단**: OS별 표식(Win `ExcludeClipboardContentFromMonitorProcessing` · mac `org.nspasteboard.ConcealedType` · KDE `x-kde-passwordManagerHint`)을 나열하고, **제외 앱은 best-effort임을 UI에 명시**하기로 했다(Maccy의 안내문 근거).
- **중복 제거**: 표현별 `blob_id`의 **조합 해시**로 판정 → 같으면 새 항목 대신 **최신으로 승격**.

**구현 순서를 수직 슬라이스 11단계**로 다시 냈다. ★ **9번(전역 단축키+포커스 복원+주입)이 끝나면 제품이 된다** — 1~8은 그 준비다. 다만 6·9가 K-1 리스크이므로 **스파이크는 1번과 병행**해 조기 검증하기로 했다.

## 4차 — 세로 밀도 우선 레이아웃 (DR-14)

사용자 지시: *"클립보드 프로그램은 많은 목록이 보이는 게 유리하므로 툴바를 좌측에 세로로 배치하고, 클립보드 내용은 세로로 최대한 많이 보일 수 있게 영역을 확보."*

★ **이 원칙 하나가 레이아웃을 결정한다 — 가로로 눕는 크롬은 항목 수를 깎는 비용이다.**

세로 공간 예산을 실제로 계산했다: 메뉴바(1) + 툴바(1) + 검색바(1) + 상태바(1) = **크롬 4줄**이던 것을, **메뉴+검색 통합(1) + 툴바 좌측 이동(0) + 상태바 옵션(0~1)** 으로 **1~2줄**까지 줄였다. **2~3줄 회수 = 28px 행 기준 56~84px = 간략 보기 항목 2~3개 더.** macOS는 메뉴가 시스템 바로 가므로 **한 줄 더 번다.**

좌측 툴바는 **폭 40px 아이콘 전용**(라벨 없음)으로 묶어 가로폭도 지켰고, 구역을 패널/항목/붙여넣기/보기/상태로 나눴다. 그룹·스니펫 **사이드 패널은 기본 접힘**(VS Code 액티비티 바 모델) — 처음 여는 사용자는 목록만 본다. 툴바는 지름길일 뿐이고 **우클릭 컨텍스트 메뉴가 같은 항목을 전부 제공**한다(VT-5).

같은 원칙을 팝업에도 적용했다 — **Maccy 푸터는 4줄**(Clear/Preferences/About/Quit)인데 우리는 **같은 4개를 1줄에** 담아 항목 3개를 더 보여준다.

⚠️ 앞서 CopyQ를 보고 **우측** 세로 툴바를 제안(D-42)했었는데 **좌측으로 확정**했다 — 메뉴·사이드 패널과 같은 편이라 시선 이동이 적고, 우측 스크롤바와 겹치지 않는다.
⚠️ beep `Toolbar`는 **가로 전용**이라 세로 지원이 필요하다. [U-1](13-ui-reuse-from-beep.md)(복사본 불변)에 따라 vendor를 고치지 않고 `nclip-ctl`에서 감싸 확장한다.

## 3차 — 화면 캡처 범위 밖 (DR-13) · 문서 되돌림

돋보기 캡처 이미지를 보고 **화면 캡처 기능을 요구로 오독**해 `19-screen-capture.md`를 작성했다. 사용자가 *"캡처기능은 대상이 아니야"* 로 정정 → **문서 삭제**하고 **DR-13(범위 밖)** 으로만 기록했다.

판단 근거를 남긴다: 클립보드 매니저의 일이 아니고, **화면 획득 계층은 클립보드 감시와 같은 크기의 플랫폼 작업**(mac 화면 기록 권한 · Wayland 포털 · 다중 모니터 DPI)이라 M1을 늦춘다. 캡처 도구(Greenshot·OS 기본)가 **클립보드에 넣어 주면 우리가 받는다**(FR-C-3) — 경계가 이미 깔끔하다.

⚠️ 같은 턴에 받은 Greenshot 대상 선택 메뉴 이미지는 CopyQ로 잘못 전달된 것이라 문서에 반영하지 않았다.

**결정 번호 충돌 정리**: 확정 `DR-13`을 추가하는 순간 기존 "확정 대기" `DR-13?`와 부딪혔다. 재발을 막으려고 **대기 계열을 `DP-n`으로 영구 분리**했다(DP-1~4). 확정되면 새 `DR` 번호를 받아 §1로 옮긴다.

## 2차 — 참조 제품 UI 해부 ([17](17-reference-ui-teardown.md))

사용자가 **Maccy 팝업 2장 · CopyQ 메인창/트레이 2장**을 제공했다. 매일 쓰는 제품의 실물이라 취향이 아니라 **검증된 패턴**으로 다뤘다.

★ **여기서 내 설계 오류 하나를 잡았다.** Maccy 팝업의 번호 단축키가 `⌘1`~`⌘9`인 이유 — **검색 필드가 항상 포커스를 갖기 때문에 맨숫자를 누르면 검색어가 된다.** 내 FR-P-8은 `1`~`9`였으니 **그대로 만들었으면 동작하지 않았을 것이다.** `Ctrl+1`~`9` / `⌘1`~`⌘9`로 정정.

Maccy에서 더 채택한 것: **개행 `↵` 표시**(한 줄 요약에서 구조가 보인다) · **긴 텍스트 가운데 생략**(끝을 자르면 식별이 어렵다) · **고정 푸터** · **미리보기 명시적 토글**(초판의 "폭 좁으면 자동 숨김"보다 낫다).

CopyQ에서 채택한 것:
- ★ **`Clipboard: <내용>`** — 현재 클립보드를 트레이 메뉴에 **별도 항목으로** 표시. *"지금 뭐가 담겨 있나"* 는 클립보드 도구의 근본 질문인데 우리에게 없던 아이디어다.
- ★ **"클립보드를 일반 문자로 붙여넣기"가 메뉴 1급 항목** — 평문 붙여넣기가 얼마나 자주 쓰이는지, 그리고 **단축키를 모르는 사용자의 경로**가 필요함을 보여준다.
- **`Item` 메뉴** — 항목 액션이 갈 자리가 실제로 필요하다(D-46 → 메뉴 구성에 반영).
- 일반 보기에서 **링크가 파란 밑줄로 렌더** · **행 높이 가변** — 우리 `RichTextView`·일반 보기 정의와 일치하고, **가변 행 높이 가상화**가 필수임을 재확인시켰다.

## 1차 — Maccy 설정 전수 → 우리 `registry()` ([14](14-settings-registry.md))

사용자가 Maccy 설정 화면 5장(General·Storage·Appearance·Ignore·Advanced)을 제공했다. [13 §2-3](13-ui-reuse-from-beep.md)에서 *"registry()만 교체하면 설정 화면 3,510 LOC가 그대로 산다"* 고 했으니, **그 교체 데이터를 만들 재료**가 온 셈이다. 발명하지 않고 **먼저 베끼고 그 위에 우리 것을 더했다.**

★ **사실 오류를 하나 잡았다.** Storage 탭에 `Save: Files / Images / Text`가 명확히 있다 — **Maccy는 파일을 저장한다.** [03](03-competitive-landscape.md)에서 *"파일 캡처 미확인"* → 이후 *"없어서 아쉬운 지점"* 으로 서술한 것은 **틀렸다.** 매트릭스(3/6→4/6)·§5-4 표·U-4를 정정했다. 실제 우위는 **원본 포맷 보존**(PPT 도형·Excel 수식 왕복)이다.

**설계 통찰로 채택한 것:**
- ★ **수식 키가 설정을 덮어쓴다** — 기본값은 체크박스 2개, 그때그때 다른 동작은 `⌥`(복사만)/`⌘`(복사+붙여넣기)/`⇧⌘`(평문+붙여넣기)로 즉석에서. **설정을 바꾸러 갈 필요가 없다.** 우리 붙여넣기 4모드에 그대로 적용(D-38).
- ★ **"다음 1건만 무시"**(`⌥⇧` 클릭) — 토글은 다시 켜는 걸 잊는데 이건 안 잊는다. **실수 방지 설계**라 채택.
- ★ **개수 상한 + 실사용량 표시**(`200` 옆에 `189.3 MB`) — [06 §4](06-storage-design.md)에서 *"개수보다 용량이 정직하다"* 고 썼는데, Maccy의 절충이 더 낫다. **둘 다 한다.**
- ★ **무시는 3중 구조**(앱 / pasteboard 타입 / 정규식). 그리고 ⚠️ **Maccy 자신이 "앱 기반은 bullet-proof가 아니니 pasteboard types를 쓰라"** 고 적어 뒀다 — 우리가 **FR-S-1(표식 존중)을 FR-S-2(제외 앱)보다 위에 둔 판단**이 실사용 제품의 안내문으로 확인됐다.
- ★ **종료 시 기록 비우기 + 시스템 클립보드까지** — 우리에게 없던 항목. 공용 PC·화면 공유에서 의미가 크다.
- **검색 모드를 설정으로**(Exact/Fuzzy/Regex) — 우리는 *"정규식은 메인창만"* 으로 정했었다. **절충**: 설정 택일(기본 Exact) + 메인창 검색바 `.*` 토글 **둘 다**(D-39).
