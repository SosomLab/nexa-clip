## 1차 — Windows 자리 최신화: Linux 작업 38커밋이 **Windows·mac test 빌드**를 깨뜨렸다

사용자 요청 *"저장소 최신화 및 변경사항 분석"*. `origin/main` 대비 **38커밋 뒤**(08-29 1차 ~ 08-30 3차 · Linux
자리 작업 전량) → fast-forward. 그 자리에선 green이었지만 **Windows에서 `cargo test`가 컴파일조차 안 됐다**.

### 무엇이 깨졌나 — `--all-targets`(test cfg)만 깨진다

`cargo check --workspace`(lib만)는 3-OS 모두 통과한다. 깨지는 것은 **test cfg 빌드**뿐이다.
`lib.rs`는 `watch_linux`를 `#[cfg(any(all(unix, not(macos)), test))]` 로 두어 **순수부(타깃 정규화·지문)를
다른 OS의 test 빌드에서도 검증**한다(autostart 선례). 08-30 2차가 그 안에서 `wayland_probe::has_data_control()`
을 부르게 했는데 그 함수는 `#[cfg(target_os = "linux")]` 한정이라 **Windows·mac test 빌드에 없다**.

| # | 결함 | 조치 |
|:--:|---|---|
| ① | `E0425 has_data_control` 없음 — Windows·mac **test 빌드 실패**(lib은 통과라 `cargo check`로는 안 보인다) | `#[cfg(not(target_os = "linux"))]` 상수 거짓 짝 — Wayland 없는 OS의 사실 |
| ② | `launcher_content` **dead_code**(clippy `-D warnings`) — `test` cfg에 들어 있는데 **박제 테스트가 없다** | 계약 테스트 추가 — `Exec=… tray` · `StartupWMClass` · `Icon`(Dock 아이콘 근거) |

**실측(Windows)**: **350 테스트** 통과 · `clippy --all-targets -D warnings` 클린 ·
`fmt --check` 클린 · **크로스 `--all-targets` 3타깃 클린**(win-msvc · linux-gnu · aarch64-darwin).

### 왜 병합됐나 — CI는 잡았다, **green을 기다리지 않았다**

워크플로는 3-OS × `clippy --all-targets` + `test`를 **이미 돌린다**. 도구는 잡았고,
다만 **run `33262111549`(main 최신 병합)이 windows·macos 둘 다 failure 인 채 남아 있었다** —
[docs/16 §3](../16-doc-git-conventions.md) *"main은 항상 green"* 위반. 한 OS 자리에서 작업할 때
병합 후 green 확인이 생략되기 쉽다.

→ **단일 OS 자리에서도 가능한 예방**: 병합 전
`cargo clippy --workspace --all-targets --target {x86_64-pc-windows-msvc, x86_64-unknown-linux-gnu, aarch64-apple-darwin}`.
크로스 **체크**는 링커 없이 돌고, 이 부류(cfg 짝 누락·dead_code)를 전부 잡는다.

## 2차 — Windows 실기 라운드: 결함 둘 수정 + ★ "서식 유실"은 Word 설정이었다

사용자 실기 보고 — ① 작업표시줄·타이틀바가 일반 창 아이콘 ② ⇧Enter가 붙여넣기 대신 **팝업만 다시 연다**
③ 팝업 원본 붙여넣기에서 **빨간색 유실**(굵게는 남음 · 직접 Ctrl+V는 정상). 통과 보고: 테마 추종 ·
닫기=트레이 · 에코 승격 · `v` 유출 없음 · 썸네일 · 트레이 재복사 승격 · 툴팁.

### ① 창 아이콘 부재 (`1a21bcc`)

트레이만 쓰던 `icon_rgba()`를 [`icon.rs`](../../crates/nexa-clip/src/icon.rs)로 올려 세 창(설정·팝업·데모)에
`with_window_icon`(+Windows `with_taskbar_icon`) 부착. Linux Dock 톱니바퀴(08-30)의 Windows판. **실기 통과 ✓**

### ② ⇧Enter = 팝업 재열림 (`03e1c26`)

원인 둘이 겹쳤다: ⓐ 평문 주입이 `Ctrl+Shift+V`를 쐈다 — **우리 자신의 전역 단축키**라 `RegisterHotKey`가
시스템 전역에서 가로채 팝업이 도로 열린다. 재적재가 이미 평문 표현만 올리므로 **평문도 `Ctrl+V`**(Linux 포털
경로와 동일 · 4모드 키 배선은 T-15b). ⓑ ⇧Enter·⇧클릭 직후엔 **물리 Shift가 아직 눌린 채**라 주입한 Ctrl+V와
합쳐져 역시 그 조합이 된다 → `GetAsyncKeyState`로 눌린 수식 키(Shift·Alt·Win)를 **먼저 떼고 주입 후 되누른다**
(Win+V = OS 클립보드 기록 오발도 함께 차단). **실기 통과 ✓** — 이전 라운드의 "클릭 무동작"도 ⇧클릭이 이
결함에 걸린 것이었다. 곁다리: `paste.rs` raw NUL 2개 이스케이프(08-29 `watch.rs` 결함 ① 동일 부류 — git
바이너리 취급 해소).

### ③ ★ "빨간색 유실" — 우리 결함이 아니라 **Word의 붙여넣기 분류 + 설정**

증거 사슬(전부 실측):

1. **왕복 진단**([`clip_roundtrip`](../../crates/nclip-plat/examples/clip_roundtrip.rs) 신설) — Word 복사
   17표현을 팝업과 같은 경로(`set_reps`)로 재게시 → **HGLOBAL 15표현 전부 바이트 동일**(핸들 포맷
   `CF_ENHMETAFILE`·`CF_METAFILEPICT`만 유실 — 텍스트 서식과 무관).
2. **`--no-ole` 실험** — 주인 잃은 OLE 사설 포맷 9종을 빼도 증상 그대로(사용자 실기) → 포맷 구성도 아니다.
3. **Word COM 실험실**(scratchpad `word_lab2.ps1`) — 같은 재게시본을 붙여넣기 모드별로:
   `원본 서식 유지(16)` = **빨강 유지** · `서식 병합(20)` = **굵게 유지·색 자동(검정)** — 증상 재현.
4. 이 PC Word 옵션 실측: 문서 간 = 원본 유지(0) · ★ **다른 프로그램에서 = 서식 병합(1)**.

즉 직접 Ctrl+V는 "Word 출처"로 분류돼 원본 유지, 우리 재게시는 클립보드 주인이 nexa-clip이라 **"다른
프로그램" 분류 → 서식 병합 → 색만 유실**. 바이트가 동일해도 소용없는 이유. **Win+V(클립보드 기록)·Ditto·
CopyQ 전부 같은 조건**이다. 조치 = 사용자 안내(즉석: 붙여넣기 옵션 → 원본 서식 유지 · 영구: Word 옵션
"다른 프로그램에서 붙여넣기" = 원본 서식 유지) — [docs/21 §1-3](../21-manual-test.md) 기록.

### 계약 재정의 하나

"팝업 연 채 재복사 = 커서 첫 줄"은 **구조상 불가**(팝업은 포커스를 잃으면 닫힌다 — 다른 앱에서 복사하는 순간
닫힘) → *"재복사 후 다시 열면 커서 첫 줄"* 로 고쳐 적는다.

## 4차 — ★ T-16 1단: 암호화 영속 — "저장소: 2개 복원"

DR-37 확정 30분 만에 착수(브랜치 `feat/store-persistence`). 이식 원본 = beep `nbeep-store/sealed.rs`
(봉투 그대로 · 매직/도메인만 치환) + `.locked` 보관 문법. 세그먼트는 beep의 도메인 특화(그룹·신뢰)와
달라 **clip 도메인으로 새로 설계**: append-only 이벤트 로그(Add/Touch/Remove) + 재생 + 열 때 압축.

| 층 | 내용 |
|---|---|
| `sealed` | ChaCha20-Poly1305 · 도메인 분리(레코드↔blob 바꿔치기 불가) · fail-closed |
| `keys` | 마스터 = 무작위 → `device.key` 래핑 한 겹(D-21 제약 — 패스프레이즈는 키 파일 교체만으로 후속) · 불일치 = `.locked` 보관 + 새 출발 |
| 로그 | 레코드마다 AEAD · 잘린 꼬리 관용(크래시) · 죽은 이벤트 3배 → 압축 |
| blob | 16KiB↑ 표현 · `blob_id = H("nclip/blob-id-v1"‖master‖H(평문))` — 키 있는 파생(확인 공격 오라클 없음) · 같은 평문 = 한 파일 · 참조 0 = 삭제 |
| 이력 | 항목 **id**(복원 후 이어짐) · ★ **pinned**(축출이 핀을 지킴 — T-18b0 기초) · 교체는 id 유지 |
| 셸 | 시작 복원 → push 결과를 add/touch/remove로 · `sec.clear_on_quit` = 종료 시 wipe · 열기 실패 = NullStore 강등(DR-31) |

**스모크 실측**(상주 자동 구동): 복사 2건 → 강제 종료 → 재시작 `저장소: 2개 복원` → 같은 내용
재복사 = 승격(증식 없음) → 재시작에도 2개. 디스크에 평문이 없는 것을 테스트로 박제
(`nothing_on_disk_is_plaintext`).

**정직한 한계(v1)**: `device.key`가 데이터 폴더에 평문 — 부분 유출은 막지만 폴더째 복사엔 못 버틴다.
OS 비밀 저장(DPAPI·Keychain) 결합 + 패스프레이즈 래핑이 후속. 의존 +3(RustCrypto · beep 동일 판 ·
[10 §3](../10-decision-record.md) 기록).
