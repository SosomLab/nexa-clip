## 8차 — T-19: 이미지 격리 디코더 이식 + 셸 설정 즉시 반영

### `nclip-imgdec` — beep 격리 구조 크레이트째

beep `nbeep-imgdec`를 이름 치환으로 이식했다(main.rs 700줄 + lockdown 통합 테스트).
구조의 요점(beep R-5·FR-S-12):

| 원칙 | 실현 |
|---|---|
| ★ **본체는 이미지 파서를 링크하지 않는다** | `png`·`jpeg-decoder`는 이 워커 crate에만(의존 원장 기록 · beep과 동일) |
| 파서가 뚫려도 아무것도 못 연다 | 입력을 **다 읽은 직후 · 파싱 전에** 자신을 잠근다 — Windows 완화 정책 / Linux seccomp-bpf / macOS Seatbelt. 강등 실패 = fail-closed(exit 4) |
| 폭탄 차단 | 원본 16MiB · 픽셀 16.7M · 변 8192 · **시간 상한은 부모가 kill** |

어댑터([`nclip-plat::imgdec`])는 beep 본체 imgdec.rs의 decode/encode-raw 경로만
(아바타·와이어는 beep 도메인). `NIMG` 응답을 **본체가 재검증** — 오염된 자식이 크기를
속여도 여기서 잘린다(순수 함수라 단위 테스트).

✅ E2E — raw 8×4 RGBA → `--encode-raw`(PNG 200B) → `--max-side 64` 디코드 → **픽셀 비트
동일**. stderr에 ★ `lockdown = windows-mitigation(dynamic-code·image-load·win32k-lockout)` —
권한 강등이 이 PC에서 실제로 걸린다.

### 셸 설정 즉시 반영

게이트(민감·제외 앱·차단 URL)·이력 상한·트레이 메뉴 개수·자동 붙여넣기를 **캡처마다
설정에서 다시 읽는다** — 설정 창에서 바꾸면 다음 복사부터 산다(재시작 불요).

**실측**: **332 테스트** · clippy `-D warnings` · fmt 클린.

## 7차 — S1 퀵 팝업 1단(T-18) + 전역 단축키(T-15) — K-1 왕복이 실물이 됐다

### 흐름 — 설계(DR-24·DR-35·K-1)가 그대로 코드가 됐다

```
Ctrl+Shift+V (트레이 스레드 RegisterHotKey · docs/14 기본값)
  → paste.capture_focus()      ★ 팝업이 뜨기 "전"의 포그라운드가 대상이다 — 순서가 전부
  → 커서 위치 팝업(DR-24)       장식 없는 최상위 창 · demo S1 간략 보기 화법 + 실데이터
  → ↑↓ · 타이핑 검색            라벨 부분 일치(대소문자 무시) · 선택 따라 스크롤
  → Enter 원본 / ⇧Enter 평문    DR-35 — 평문 없는 항목은 정직하게 거절(DR-31)
  → clipboard::set_reps        재적재
  → paste.restore_and_paste    포커스 복원 + Ctrl+V 주입 (paste.auto 꺼짐 = 여기 생략)
```

- 단축키 충돌(CopyQ 등 선점)은 **등록 실패를 화면에 알린다** — 실기에서는 등록 성공.
- 팝업은 포커스를 잃으면 닫힌다(Maccy 관례).

### ⚠️ 실기가 잡은 것 — 생성 직후 `Focused(false)` 레이스

자동 검증(잠금 화면)에서 팝업이 **열리자마자 소리 없이 닫혔다**. 원인 = 창이 포커스를
받기 전에 오는 `Focused(false)`를 "상실"로 오독. **한 번이라도 받은 뒤의 상실만** 닫도록
`was_focused` 가드 — 잠금·일부 창 관리자의 초기 이벤트 순서 차이에 안전해졌다.

### 검증 — 잠금 화면의 한계까지 기록

키 주입(SendKeys·keybd_event)이 전부 무반응 + 독립 프로브(RegisterHotKey 왕복)도 침묵 —
**세션이 잠겨 있으면 입력 주입 자체가 막힌다**는 것을 확인하고, 트레이 창에
`WM_HOTKEY`를 직접 게시하는 우회로 검증했다:

| 확인 | 결과 |
|---|---|
| 단축키 등록 | ✅ "전역 단축키: Ctrl+Shift+V" |
| WM_HOTKEY → 팝업 열림 | ✅ "팝업: 열기 — 이력 1개" + **창 실존**(PID 창 열거) |
| 토글로 닫힘 | ✅ "팝업: 닫기(토글)" + 창 소멸 |
| 검색·Enter·주입 | ⏳ **사용자 실기**(잠금 화면에서는 포커스·주입 불가) |

트레이에서 선택 → 클립보드 복귀가 **처음으로 한 줄로 이어졌다**(세션 한정 · 저장소는 T-16).

### `nclip-core::history` — 규칙은 최종형 그대로

| 규칙 | 구현 |
|---|---|
| ★ 재복사 = **승격** | 동일성 = **정렬된 (표현 이름, 바이트) 전체**. 라벨 비교는 함정(같은 첫 줄, 다른 본문). FNV-1a 지문으로 거르고 바이트로 확정 — 이미지 1000개에서 전량 비교는 비싸다 |
| 연속 장면 = **교체** | D-80 `coalesces`를 `coalesces_parts`로 부품화해 재사용 — 탐색기 재게시가 이력을 불리지 않는다 |
| 상한 | `store.max_items` — 오래된 것부터. `set_cap`은 즉시 절단 |

### 재적재 — `nclip-plat::clipboard::set_reps`

가진 표현을 **이름째 전부** 게시한다(P-2 — 판단은 받는 앱 몫). 표준 이름 → 번호
역표(17개) + `RegisterClipboardFormatW`. 성공한 HGLOBAL은 시스템 소유(해제 금지),
실패분만 되돌려 해제.

⚠️ **beep 08-21 힙 오염 실측을 그대로 이식** — `OpenClipboard(NULL)`은 오픈 상태 대조가
NULL==NULL이라 둘째 호출자도 성공하고, 그 순간 `EmptyClipboard`가 상대가 잠근 HGLOBAL을
해제해 use-after-free가 된다. **호출마다 실 창(ClipGuard) + 프로세스 내 뮤텍스**.

✅ 왕복 테스트(`--ignored` · 실 클립보드): `CF_UNICODETEXT` + 등록 포맷 게시 → 감시 읽기로
바이트 일치.

### 셸 배선 — 게이트 공용화 · 에코는 승격이 처리

- `watch_cmd::Gate`에 `blocks()`를 만들어 **진단과 셸이 같은 정책**(민감 표식 · 제외 앱 ·
  브라우저 암호)을 쓴다 — 막힌 것은 화면에도 이력에도 없다.
- 트레이 우클릭 메뉴에 **최근 N개**(`ui.tray_recent_n` · 라벨 44자 절단) — 클릭 =
  `TrayEvent::Recent(i)` → 재적재. 재적재가 감시로 되돌아오면 **승격**이라 항목이 늘지
  않는다 — 에코 루프([docs/08])의 로컬판을 별도 장치 없이 처리한 셈.
- 툴팁 = "N개 보관"(이력 길이 — 이벤트 수가 아니라 실제 보관 수).

## 5차 — 자동 시작 · 닫을 때 트레이로 (사용자 요청 — beep 동일 기능 이식)

### 자동 시작 (`app.autostart` · 기본 켜짐)

beep `crates/nbeep-plat/src/autostart.rs`를 **3-OS째 이식**(이름 4곳 치환 — APP_NAME
`NexaClip` · `com.sosomlab.nexa-clip` · `nexa-clip.desktop` · `Name=Nexa Clip`).
전부 **무권한(T0)** 경로: Windows HKCU `Run` · mac `~/Library/LaunchAgents` plist ·
Linux XDG `~/.config/autostart`. 계약 테스트(plist 이스케이프·desktop 인용·`boot_sync`)째 왔다.

| 언제 | 무엇 |
|---|---|
| 설정 토글 | ★ **값 저장 + OS 등록/해제 즉시**(`drain_changes` 훅) — 값만 저장하면 아무 일도 안 일어난다 |
| `tray` 시작마다 | `boot_sync` 재동기화 — 포터블 이동으로 옛 경로가 죽는 것을 막는다 |
| 앱 밖에서 지웠으면 | ★ **존중** — 재등록하지 않고 설정을 끔으로 내린다(마커 `app.autostart_reg` — 프레임워크 이식 때 이미 와 있던 HIDDEN_KEYS를 그대로 썼다) |

### 닫을 때 트레이로 (`ui.close_to_tray` · 기본 꺼짐)

beep 사용자 확정(08-15 — *3-OS 공통 off · X = 종료(예측 가능성 우선)*)을 그대로 준용.

★ 이를 위해 `tray`가 **상주 셸**로 승격됐다 — winit `EventLoop`는 프로세스당 하나·메인
스레드 강제라, 트레이(전용 스레드)·감시(전용 스레드)가 **`EventLoopProxy`** 로 사용자
이벤트를 쏘고 메인 루프가 한 곳에서 처리한다(beep 호스트 문법):

- 시작 = **트레이만**(창 없음 — 상주 앱의 조용한 출발)
- 좌클릭/"열기" = **설정 창**(`settings_win::App`을 `ensure_window`/`request_close`/
  `hide_window`로 재사용 — 상주 모드 플래그로 단독 `settings` 명령과 동거)
- 닫기/Esc = 설정 따라 **종료 또는 숨기**(숨기면 미저장 변경 강제 수거 후 창만 걷는다)
- 감시 카운트가 200ms 폴링에서 **프록시 이벤트**로 — 유휴 CPU 0에 더 충실해졌다

✅ E2E — 켜짐: `HKCU\…\Run\NexaClip` = 현재 exe 경로(따옴표 포함) 실측 · 끔: 값 삭제 실측.
창 열고 닫기·숨기·재열기는 눈 확인(⏳ [21](../21-manual-test.md)).

**실측**: **321 테스트** · clippy `-D warnings` · fmt 클린 · 설정 25항목.

## 4차 — T-12e 트레이 상주 (Windows) · win32 선언 통합

beep `nbeep-plat/tray.rs`에서 공통 타입 + **Windows 모듈**을 이식했다.
mac 모듈은 objc2·objc2-app-kit 의존을 들여오는 결정(DR-8 원장)이 필요해 보류 —
Linux(zbus SNI)와 함께 각 실기 환경에서 이식한다. 미이식 타깃은 `spawn() = None`(정직).

### `nexa-clip tray` — 첫 상주 모양

- 아이콘은 **코드로 그린다**(32×32 라운드 스퀘어 · 청록 그라디언트 · 흰 클립보드 모티프) —
  애셋 파일을 링크에 안 끌어들인다(단일 바이너리).
- ★ **감시 통합** — 잡힌 항목 수(`has_content` 통과분)가 툴팁에 실시간 반영
  (`Nexa Clip — N개 수집`). `TrayHandle::update()` 경로의 실증이기도 하다.
- 좌클릭/열기 = 콘솔 안내(메인창은 T-18b) · 종료 = 메뉴. 최근 N개 메뉴(T-18e)는
  저장소(T-16) 뒤 — 빈 메뉴를 먼저 그리지 않는다.

### ★ 이식이 규약 충돌을 드러냈다 — `win32` 공용 선언 모듈

beep은 plat 전체가 `*mut c_void` 핸들이라 충돌이 없었지만, 우리는 `isize` 규약
(paste.rs)이다. 트레이가 자기 선언을 들고 오자 `clashing_extern_declarations`
(우리 설정 = `-D` 오류) **7건** — `watch_win`이 주석으로 경고했던 바로 그 사고다.
같은 함수의 **다른 구조체 pointee**(`WNDCLASSW`·`MSG`)까지 충돌로 잡힌다.

→ 겹치는 선언(창 클래스·메시지 루프·`SetForegroundWindow` 등 10개 함수 + 구조체 2개)을
[`nclip-plat::win32`](../../crates/nclip-plat/src/win32.rs) **한 곳으로 통합**하고
paste·watch_win·tray가 그걸 쓰게 정리했다. 한 모듈만 쓰는 함수는 그 모듈에 남긴다.

### 트레이 창이 감시 창과 다른 이유

감시(`watch_win`)는 메시지 전용 창(HWND_MESSAGE), 트레이는 **보이지 않는 일반 창** —
메시지 전용 창은 **TaskbarCreated 브로드캐스트를 못 받아** explorer 재시작 때
아이콘을 재등록할 수 없다(beep 08-15 분석 그대로).

✅ 자동 확인 — 상주 프로세스 + 감시 시작 + 복사 수집. 아이콘·메뉴·툴팁은 눈 확인(⏳).

**실측**: 316 테스트 · clippy `-D warnings` · fmt 클린.

## 3차 — T-14c 1단: 이미지 치수·축소 (`nclip-core::img` 신설)

이미지 항목이 `미리보기 준비 중` 대신 **`[이미지] 1920×1080`** 을 보여 준다.

### 경계를 먼저 정했다 — 압축 해제는 본체에 없다

beep을 먼저 봤다(재발명 금지): beep은 PNG/JPEG 디코드를 **격리 워커 프로세스**
(`nbeep-imgdec` — png·jpeg-decoder crate는 거기에만, *"본체는 이미지 파서를 절대 링크하지
않는다"* · 권한 강등까지)로 뺐다. 우리도 같은 구조로 간다 — 워커 이식은 T-19.

이번 1단은 그보다 **얕은 것만** 본체(core)에 순수 함수로:

| 함수 | 읽는 것 |
|---|---|
| `png_dimensions` | 서명 8B + IHDR 폭·높이 — **압축 해제 없음** |
| `dib_dimensions` / `bmp_dimensions` | 머리글 고정 오프셋 |
| `dib_to_rgba` | **비압축** DIB 픽셀(24/32bpp · 표준 마스크만) — beep `nbeep-plat/clipboard.rs`에서 **테스트째 이식** |
| `downscale_rgba` | 우리가 만든 RGBA — ★ **박스 평균**(최근접은 스크린샷의 가는 선·글자를 건너뛰어 썸네일이 "빈 화면"이 된다) |

상한은 beep imgdec와 동일(변 8192 · 16.7M픽셀 — 할당 폭탄 방어).
`dib_to_rgba`는 순수라 plat이 아니라 **core**에 뒀다(3-OS 테스트).

### watch 배선

`thumbnail_source`가 고른 표현의 **머리글만** 읽어 치수를 뽑고 `capture()`에 넘긴다.
blob_id는 저장소(T-16) 전까지 0 — 목록 표시는 치수만 쓴다.

✅ E2E — 모의 PNG(IHDR 1920×1080, 29바이트)를 클립보드에 올려 `[이미지] 1920×1080` 확인.

## 2차 — 차단 목록을 설정으로 (사용자 요청: "직접 추가/삭제/수정")

하드코딩이던 차단 대상을 **설정 값**으로 옮겼다. 자유 텍스트(`RadioInput(&[], _)` +
`FREE_TEXT_KEYS`) 한 줄에 `;` 구분 — 리스트 편집 컨트롤 없이 기존 프레임워크로 해결.

| 키 | 무엇 | 기본 |
|---|---|---|
| `sec.conceal_urls` | 차단할 출처 URL 접두 | ★ **코어 기본 목록 그대로**(레지스트리 테스트가 [`PASSWORD_MANAGER_URL_PREFIXES`]와의 동기화를 강제 — 코어에 추가하고 기본값을 잊으면 즉시 깨진다) |
| `sec.exclude_apps` | 제외 앱 이름(FR-S-2 표시층 첫 구현) | 비어 있음 — **목록의 존재가 곧 의사**라 토글이 따로 없다 |

- 코어: [`parse_block_list`](../../crates/nclip-core/src/capture.rs)(`;` 구분·공백 정리) ·
  [`url_in_prefixes`](일반형 — 사용자 목록으로 판정) · [`app_in_list`](대소문자 무시 **완전
  일치** — ⚠️ 부분 일치면 `Edge`가 `EdgeUpdater`까지 잡는다).
- ★ **사용자가 목록의 주인이다** — 기본 항목을 지우면 그 항목은 더 안 막는다(E2E로 박제).
  `sec.conceal_urls`를 통째로 비우면 재시작 때 기본 목록으로 복귀(설명문에 명시).
- ✅ E2E 셋 — ① msedge 소유 클립보드 + `msedge` 등록 → `(제외 앱 — msedge …)` ②
  `myapp://secret`만 남긴 목록 + 그 출처 → 차단 ③ 같은 상태에서 Edge 출처 → **통과**.
  ⚠️ `Set-Clipboard`는 소유 창이 없어 출처 앱이 안 잡힌다(제외 앱 검증 수단이 못 된다)는
  것도 이번에 확인.

**실측**: **314 테스트** · clippy `-D warnings` 클린 · 설정 24항목.

## 1차 — DR-36 실기: Chrome ✅ · ⚠️ Edge는 경로가 달랐다

옵션(`sec.conceal_browser_pw`)을 켠 사용자 실기:

| 브라우저 | 결과 |
|---|---|
| **Chrome** 비밀번호 관리자 | ✅ 3건 전부 `(브라우저 암호 관리자 복사 — 기록하지 않습니다)` |
| **Edge** | ❌ **그대로 기록됨** |

### 원인 — 접두 목록에 실경로가 없었다

스크린샷 주소창이 원인을 바로 줬다: 이 Edge 버전(139대)의 암호 관리자는

```
edge://settings/autofill/passwords/details?domain=0daydown.com
```

— `edge://wallet/`(구현 시 추정)이 아니라 **`settings/autofill` 아래**다.
어제 실기 캡처의 `Chromium internal source URL 60 B`도 돌아보면 이 경로 길이와 맞는다.

### 조치

- [`is_password_manager_url`](../../crates/nclip-core/src/capture.rs)에
  `edge://settings/autofill/passwords` 추가 — ⚠️ `edge://settings/autofill`(주소·카드 일반)은
  넣지 않았다(암호 하위만 민감). 실기 URL **그대로** 테스트에 박제.
- 모의 E2E — 해당 출처 + 가짜 암호 → 마스킹 확인.

★ DR-36이 스스로 예고한 실패 모드다 — *"URL 목록은 브라우저 버전에 따라 늙는다.
실기에서 만나면 추가한다(D-75와 같은 운영)"*. 첫 노화가 하루 만에 왔고, 운영 방식이 맞았다.

**실측**: 311 테스트 · clippy `-D warnings` 클린.

### 재점검 결과

✅ **Edge도 정상 차단**(사용자 실기: *"엣지에서도 복사 기능이 정상 차단됌"*) —
**T-21b 통과**(Chrome + Edge). DR-36은 실기 두 브라우저로 닫혔다.
