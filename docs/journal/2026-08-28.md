## 3차 — T-14c 1단: 이미지 치수·축소 (`nclip-core::img` 신설)

이미지 항목이 `미리보기 준비 중` 대신 **`[이미지] 1920×1080`** 을 보여 준다.

### 경계를 먼저 정했다 — 압축 해제는 본체에 없다

beep을 먼저 봤다(재발명 금지): beep은 PNG/JPEG 디코드를 **격리 워커 프로세스**
(`nbeep-imgdec` — png·jpeg-decoder crate는 거기에만, *"본체는 이미지 파서를 절대 링크하지
않는다"* · 권한 강등까지)로 뺐다. 우리도 같은 구조로 간다 — 워커 이식은 T-19.

이번 1단은 그보다 **얕은 것만** 본체(core)에 순수 함수로:

| 함수 | 읽는 것 |
|---|---|
| `png_dimensions` | 서명 8B + IHDR 폭·높이 — **압축 해제 없음** |
| `dib_dimensions` / `bmp_dimensions` | 머리글 고정 오프셋 |
| `dib_to_rgba` | **비압축** DIB 픽셀(24/32bpp · 표준 마스크만) — beep `nbeep-plat/clipboard.rs`에서 **테스트째 이식** |
| `downscale_rgba` | 우리가 만든 RGBA — ★ **박스 평균**(최근접은 스크린샷의 가는 선·글자를 건너뛰어 썸네일이 "빈 화면"이 된다) |

상한은 beep imgdec와 동일(변 8192 · 16.7M픽셀 — 할당 폭탄 방어).
`dib_to_rgba`는 순수라 plat이 아니라 **core**에 뒀다(3-OS 테스트).

### watch 배선

`thumbnail_source`가 고른 표현의 **머리글만** 읽어 치수를 뽑고 `capture()`에 넘긴다.
blob_id는 저장소(T-16) 전까지 0 — 목록 표시는 치수만 쓴다.

✅ E2E — 모의 PNG(IHDR 1920×1080, 29바이트)를 클립보드에 올려 `[이미지] 1920×1080` 확인.

**실측**: 테스트 +9 · clippy `-D warnings` 클린.

## 2차 — 차단 목록을 설정으로 (사용자 요청: "직접 추가/삭제/수정")

하드코딩이던 차단 대상을 **설정 값**으로 옮겼다. 자유 텍스트(`RadioInput(&[], _)` +
`FREE_TEXT_KEYS`) 한 줄에 `;` 구분 — 리스트 편집 컨트롤 없이 기존 프레임워크로 해결.

| 키 | 무엇 | 기본 |
|---|---|---|
| `sec.conceal_urls` | 차단할 출처 URL 접두 | ★ **코어 기본 목록 그대로**(레지스트리 테스트가 [`PASSWORD_MANAGER_URL_PREFIXES`]와의 동기화를 강제 — 코어에 추가하고 기본값을 잊으면 즉시 깨진다) |
| `sec.exclude_apps` | 제외 앱 이름(FR-S-2 표시층 첫 구현) | 비어 있음 — **목록의 존재가 곧 의사**라 토글이 따로 없다 |

- 코어: [`parse_block_list`](../../crates/nclip-core/src/capture.rs)(`;` 구분·공백 정리) ·
  [`url_in_prefixes`](일반형 — 사용자 목록으로 판정) · [`app_in_list`](대소문자 무시 **완전
  일치** — ⚠️ 부분 일치면 `Edge`가 `EdgeUpdater`까지 잡는다).
- ★ **사용자가 목록의 주인이다** — 기본 항목을 지우면 그 항목은 더 안 막는다(E2E로 박제).
  `sec.conceal_urls`를 통째로 비우면 재시작 때 기본 목록으로 복귀(설명문에 명시).
- ✅ E2E 셋 — ① msedge 소유 클립보드 + `msedge` 등록 → `(제외 앱 — msedge …)` ②
  `myapp://secret`만 남긴 목록 + 그 출처 → 차단 ③ 같은 상태에서 Edge 출처 → **통과**.
  ⚠️ `Set-Clipboard`는 소유 창이 없어 출처 앱이 안 잡힌다(제외 앱 검증 수단이 못 된다)는
  것도 이번에 확인.

**실측**: **314 테스트** · clippy `-D warnings` 클린 · 설정 24항목.

## 1차 — DR-36 실기: Chrome ✅ · ⚠️ Edge는 경로가 달랐다

옵션(`sec.conceal_browser_pw`)을 켠 사용자 실기:

| 브라우저 | 결과 |
|---|---|
| **Chrome** 비밀번호 관리자 | ✅ 3건 전부 `(브라우저 암호 관리자 복사 — 기록하지 않습니다)` |
| **Edge** | ❌ **그대로 기록됨** |

### 원인 — 접두 목록에 실경로가 없었다

스크린샷 주소창이 원인을 바로 줬다: 이 Edge 버전(139대)의 암호 관리자는

```
edge://settings/autofill/passwords/details?domain=0daydown.com
```

— `edge://wallet/`(구현 시 추정)이 아니라 **`settings/autofill` 아래**다.
어제 실기 캡처의 `Chromium internal source URL 60 B`도 돌아보면 이 경로 길이와 맞는다.

### 조치

- [`is_password_manager_url`](../../crates/nclip-core/src/capture.rs)에
  `edge://settings/autofill/passwords` 추가 — ⚠️ `edge://settings/autofill`(주소·카드 일반)은
  넣지 않았다(암호 하위만 민감). 실기 URL **그대로** 테스트에 박제.
- 모의 E2E — 해당 출처 + 가짜 암호 → 마스킹 확인.

★ DR-36이 스스로 예고한 실패 모드다 — *"URL 목록은 브라우저 버전에 따라 늙는다.
실기에서 만나면 추가한다(D-75와 같은 운영)"*. 첫 노화가 하루 만에 왔고, 운영 방식이 맞았다.

**실측**: 311 테스트 · clippy `-D warnings` 클린.
