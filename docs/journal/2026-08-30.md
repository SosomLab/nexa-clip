## 2차 — 사용자 실기가 잡은 셋: Wayland 주입은 포털 · ★ wl-paste 폴링이 포커스를 뺏는다 · Dock 톱니바퀴

### ① 붙여넣기 안 됨 → Wayland 키 주입 = xdg 포털 `RemoteDesktop`

로그는 `붙여넣기: 포커스 복원 + 키 주입 ok` — X 서버 왕복은 성공했는데 앱에 안 갔다. 실측 `ps -C Xwayland`:
**`-enable-ei-portal`**. 이 모드의 XTest는 X 서버가 받아도 Wayland 앱 전달은 **libei → 포털 권한**을 거친다(권한 없는
X 클라이언트의 키는 버려진다). 1차의 *"Mutter가 가상 입력 장치로 배달"* 은 이 PC에선 **틀렸다 — 정정**.

→ [`remote_input_linux.rs`](../../crates/nclip-plat/src/remote_input_linux.rs) 신설: `CreateSession` → `SelectDevices(keyboard ·
persist_mode=2)` → `Start`(첫 회 **"원격 제어 허용" 대화창** = ⑤의 정체) → `NotifyKeyboardKeycode`(evdev `KEY_LEFTCTRL`=29 ·
`KEY_V`=47). `restore_token`을 `data/portal-remotedesktop.token`에 두면 다음 실행부터 대화창이 없다(실측 ✓ — 36B 토큰 ·
재기동 `키 주입 권한: ok`). 백엔드 이름 `wayland-portal-remotedesktop` · XTest는 포털 없는 컴포지터의 폴백으로만.
워밍업은 기동 때 **별도 스레드**(승인까지 트레이 기동을 막지 않게 — 처음엔 막았다가 고침).

### ④ ★ 포커스 플랩 + 톱니바퀴 창 → 원인은 감시 폴링의 `wl-paste`

**GNOME(Mutter 50)에는 data-control이 없다**(어제 실측). 그러면 wl-clipboard는 **매 호출 숨은 창을 만들어 키보드
포커스를 받은 뒤** 셀렉션을 읽는다(Wayland 보안 모델). 500ms 폴링 = 초당 두 번 포커스가 뺏겼다 돌아오고, `.desktop` 없는
`wl-paste` 창이 Dock에 톱니바퀴로 깜빡인다. 어제 하네스 8/8은 사람이 옆에서 타이핑하지 않아 못 본 것 — **자동 실기의
사각**이다(기록: 폴링형 도구 스폰은 "포커스를 건드리는가"를 반드시 본다).

→ [`wayland_probe.rs`](../../crates/nclip-plat/src/wayland_probe.rs): 레지스트리 1회 왕복으로 `zwlr/ext_data_control_manager`
유무를 **사실로** 판정. `pick_backend` = data-control 있을 때만 `wl-paste`, 없으면 **XWayland `xclip`**(`xwayland-xclip`) —
Mutter가 Wayland↔X11 셀렉션을 **양방향** 동기화한다(어제 XWayland 7/7이 근거). 쓰기(`wl-copy`)도 같은 규칙.
실측: `wl-paste` 스폰 0 · Wayland 쪽 복사(`wl-copy` · 사용자 스크린샷 `[이미지] 1230×700`) 캡처 ✓ · `xclip` 재적재 →
`wl-paste`도 `delta four` ✓.

## 1차 — ★ Linux 트레이(T-12e) + K-1 Linux(T-9b) — 제품 루프가 Linux에서도 이어진다

사용자 요청 — *"1(트레이 Linux), 2(K-1 Linux)를 순차로. 둘 다 nexa-beep를 참고하면 쉽게."*
어제 4차가 남긴 "이 PC에서 지금 가능한 것" 1·2번이다. 브랜치 `feat/linux-tray-paste`.

### 설계 판단 — 왜 이렇게

- **트레이 = SNI(D-Bus)**. GNOME은 워처가 셸 확장(`ubuntu-appindicators`)이다 — 없으면 `spawn`이 `None`을
  돌리고 호스트가 *"확장을 켜라"* 고 사실을 말한다(`tray_failure_hint`).
- **전역 단축키 = 포털**. `BindShortcuts`는 셸이 **사용자 확인 대화창**을 띄운다(첫 등록 · 사용자가 조합을 바꿀 수
  있어 `hotkey_label()`이 셸이 확정한 설명을 돌려준다). 포털 부재/거부 = `HotkeyStatus(false)` + 사유.
- **"열기"가 창을 앞으로** — Wayland는 `set_visible`/`focus_window`가 no-op(beep 08-29 ④). appindicator가 클릭 때
  `ProvideXdgActivationToken`으로 셸 토큰을 주므로 기존 창은 `wlactivate::activate`, **새 창은 winit
  `with_activation_token`** 으로 쓴다. 토큰 없으면 `request_user_attention`(Dock 강조) 폴백.
- **K-1 Linux는 세션이 갈린다** — X11: `GetInputFocus` 기억 → `_NET_ACTIVE_WINDOW`+`SetInputFocus` → XTest `Ctrl+V`.
  **Wayland: 남의 창을 활성화할 수 없다.** 대신 **팝업이 닫히면 컴포지터가 직전 창에 포커스를 돌려준다** — `restore`는
  120ms 정착 대기뿐이고, 주입은 **XWayland(`DISPLAY=:0`)의 XTest**(Mutter가 가상 입력 장치로 Wayland 앱에도
  배달). `DISPLAY`가 없으면 `WaylandNoInjection`으로 정직 강등. 그래서 호스트의 **"팝업을 먼저 닫고 → 재적재 →
  주입" 순서**(08-28 `pick`)가 Linux에서는 정확성의 전부다.
- **평문도 `Ctrl+V`** — 호스트가 평문 표현만 올린다. Windows의 `Ctrl+Shift+V` 관례는 Linux에선 우리 전역 단축키와
  겹친다.
- **클립보드 쓰기 1단 = 표현 한 개** — `wl-copy`/`xclip` 모두 `--type` 하나. `pick_rep`: `text/uri-list` > `image/png` >
  `text/plain` > `text/html`. 다중 표현은 자체 `wl_data_source`(팝업 창의 입력 시리얼 필요)로 후속.
- **창 app_id = `nexa-clip`**(`win_name` 단일 지점) — beep 실기 ③(없으면 Dock이 톱니바퀴 + "알 수 없음").
