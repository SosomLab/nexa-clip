### ① 첫 번만 붙는다 → 주입은 **다음 루프 바퀴**에

### ④ ★ 포커스 플랩 + 톱니바퀴 창 → 원인은 감시 폴링의 `wl-paste`

## 1차 — ★ Linux 트레이(T-12e) + K-1 Linux(T-9b) — 제품 루프가 Linux에서도 이어진다

사용자 요청 — *"1(트레이 Linux), 2(K-1 Linux)를 순차로. 둘 다 nexa-beep를 참고하면 쉽게."*

### 설계 판단 — 왜 이렇게

- **트레이 = SNI(D-Bus)**. GNOME은 워처가 셸 확장(`ubuntu-appindicators`)이다 — 없으면 `spawn`이 `None`을
  돌리고 호스트가 *"확장을 켜라"* 고 사실을 말한다(`tray_failure_hint`).
- **전역 단축키 = 포털**. `BindShortcuts`는 셸이 **사용자 확인 대화창**을 띄운다(첫 등록 · 사용자가 조합을 바꿀 수
  있어 `hotkey_label()`이 셸이 확정한 설명을 돌려준다). 포털 부재/거부 = `HotkeyStatus(false)` + 사유.
- **"열기"가 창을 앞으로** — Wayland는 `set_visible`/`focus_window`가 no-op(beep 08-29 ④). appindicator가 클릭 때
  `ProvideXdgActivationToken`으로 셸 토큰을 주므로 기존 창은 `wlactivate::activate`, **새 창은 winit
  `with_activation_token`** 으로 쓴다. 토큰 없으면 `request_user_attention`(Dock 강조) 폴백.
- **K-1 Linux는 세션이 갈린다** — X11: `GetInputFocus` 기억 → `_NET_ACTIVE_WINDOW`+`SetInputFocus` → XTest `Ctrl+V`.
  **Wayland: 남의 창을 활성화할 수 없다.** 대신 **팝업이 닫히면 컴포지터가 직전 창에 포커스를 돌려준다** — `restore`는
  120ms 정착 대기뿐이고, 주입은 **XWayland(`DISPLAY=:0`)의 XTest**(Mutter가 가상 입력 장치로 Wayland 앱에도
  배달). `DISPLAY`가 없으면 `WaylandNoInjection`으로 정직 강등. 그래서 호스트의 **"팝업을 먼저 닫고 → 재적재 →
  주입" 순서**(08-28 `pick`)가 Linux에서는 정확성의 전부다.
- **평문도 `Ctrl+V`** — 호스트가 평문 표현만 올린다. Windows의 `Ctrl+Shift+V` 관례는 Linux에선 우리 전역 단축키와
  겹친다.
- **클립보드 쓰기 1단 = 표현 한 개** — `wl-copy`/`xclip` 모두 `--type` 하나. `pick_rep`: `text/uri-list` > `image/png` >
  `text/plain` > `text/html`. 다중 표현은 자체 `wl_data_source`(팝업 창의 입력 시리얼 필요)로 후속.
- **창 app_id = `nexa-clip`**(`win_name` 단일 지점) — beep 실기 ③(없으면 Dock이 톱니바퀴 + "알 수 없음").
