## 1차(win) — ★ **기기 간 파일 전파**(경로 목록 · 적응형 수신) + 설정 3종 (사용자 요청 09-12)

**요청**: "현재 파일 복사시 파일이 복사되는 기능이 구현된 상태인지 확인" → "**기기간 전파 기능 구현해줘 · 관련된 제약이나 설정이 필요하면 설정에 옵션을 넣어줘**".

**확인 결과(선행)**: 로컬 왕복(복사 → 목록 → 붙여넣기 = 진짜 파일)은 **Win/mac 완비**였고, 빠져 있던 것은 **기기 간 전파** 한 자리였다 —
`syncitem::from_reps`가 `ClipKind::Files`면 `None`을 돌려주고 주석에 *"경로 목록 전파는 후속"* 이라고 적혀 있었다(09-04 1단 범위 = 평문·PNG).

| 축 | 내용 |
|---|---|
| **와이어** | 파트 하나 추가 — `x-nclip/paths`(**NUL 구분 원본 경로**) + 기존 `text/plain`(경로 줄 목록). 이름 순서 고정(`paths` → `image/png` → `text/plain`). ★ **구버전(≤0.1.3)은 미지 파트를 조용히 버리고**(`to_local_reps`의 전방 호환 규칙) 함께 온 텍스트를 경로 글자로 붙인다 — 앞뒤 호환이 공짜로 섰다 |
| **왜 URI가 아닌가** | ① 실재 판정(P-1)은 **OS 경로**로 해야 하고 ② URI 왕복은 Windows 드라이브 문자·역슬래시에서 손실이 나기 쉽고 ③ 구분자 `\0`은 **어느 OS에서도 경로에 못 들어가는 유일한 바이트**다(`\n`은 Linux 파일명에 들어갈 수 있어 목록이 조용히 쪼개진다) |
| **송신** | `from_reps_limited(reps, Option<usize>)` — `None` = `sync.files` 끔(경로 텍스트조차 안 보낸다 · 사용자가 공유하지 않기로 한 것이다) · `Some(n)` = `sync.files_max`로 자르고 **자른 사실을 로그로**. 정책은 **UI 스레드가 설정에서 읽어 워커에 값으로** 넘긴다(설정 변경이 다음 복사부터 바로 산다) |
| **경로를 못 뽑는 파일 항목** | 탐색기 **잘라내기**는 `CF_HDROP` 없이 `Shell IDList Array`(PIDL)만 온다(docs/27 ⑧) → **보내지 않는다**(지어내기 금지 · DR-31) |
| **수신 = 적응형**(docs/08 §3-1 안 "다") | **세션 스레드**에서 경로 실재를 확인해 갈라 놓는다 — 전부 실재 → **파일 표현**(P-2) · 하나라도 부재 → **경로 텍스트**(P-3) · **어느 쪽이었는지 항상 로그**(P-4). ⚠️ 실재 확인 = 파일 시스템 접근이라 **UI 스레드는 건드리지 않는다**(DR-41) |
| **파일 표현 생성** | `nclip_plat::clipboard::file_reps(paths)` 신설 — Win `CF_HDROP`(DROPFILES wide + 이중 NUL) + `Preferred DropEffect`(복사로 못 박음) · mac `NSFilenamesPboardType`(XML plist) + `public.file-url`(첫 경로) · Linux `x-special/gnome-copied-files` + `text/uri-list` |
| ★ **Linux 게시 순위 교정** | `wl-copy`/`xclip`은 `--type` 하나뿐이라 **한 표현만** 나간다. 붙여넣기로 **파일이 실제로 생기는** 것은 `x-special/gnome-copied-files` 쪽이라 `pick_rep` 1순위로 올렸다(종전 `text/uri-list`). 로컬에서 캡처한 파일 항목의 재게시에도 같이 적용되는 개선 |
| **공용 함수 승격** | `capture::paths_of(&[RawRep])`(= `ClipSnapshot::file_paths` 본체 — 스냅숏이 없는 송신 자리와 **같은 함수**) · `capture::file_uri`(퍼센트 인코딩 · `parse_uri_list`의 역방향) · `capture::parse_plist_paths`(XML plist만 · 이진 plist는 **빈 목록**) |
| **에코** | 받아서 게시한 것을 감시가 다시 읽어도 `from_reps`가 **같은 바이트**를 만든다(경로·텍스트가 동일) → 지문 일치로 되돌려 보내지 않는다. 09-04의 `⇄` 재전송 금지와 이중으로 막힌다 |

### 설정 3종 (설정 → 동기화)

| 키 | 종류 | 기본 | 뜻 |
|---|---|---|---|
| `sync.files` | Toggle | **on** | 파일 경로 전파 — 끄면 파일 항목은 아예 보내지 않는다 |
| `sync.files_paste` | Radio | `adaptive` | 받은 파일 붙여넣기 — **적응형**(경로가 전부 있으면 파일) / **경로 텍스트만**(파일 시스템을 건드리지 않는다) |
| `sync.files_max` | Number(100·1000·10000) | **1000** | 한 항목에 실어 보낼 경로 수 상한 — 폴더 통째 선택 같은 폭주만 자른다 |

i18n 8키 × 4언어. `sync.files_paste`는 세션 스레드가 읽는 값이라 **부팅(`spawn_if_enabled`)·변경(설정 창)** 두 자리에서 전역 스위치에 박는다(`set_files_as_text` — `set_policy`와 같은 화법). 송신 둘은 복사 때마다 설정을 읽으므로 배선이 없다.

### 한계 · 후속(T-51)

1. **mac 다중 파일 게시는 실기 미확인** — `public.file-url`은 타입 하나에 URL 하나라 legacy `NSFilenamesPboardType`(XML plist)을 함께 낸다. 못 읽어도 **경로 텍스트는 항상 함께 게시**되므로 조용히 실패하지는 않는다.
2. **목록 UI 배지 미구현** — docs/08 §3-2의 *"`\u26a0` 이 PC에 없음 / `\u2705` 접근 가능"* 행별 표시. 지금은 **로그**로만 알린다.
3. **실재 확인은 수신 시 1회** — docs/08 P-1의 문자 그대로는 *"붙여넣기 직전"* 이지만, 붙여넣기는 UI 스레드에서 일어나고 끊긴 UNC 경로 확인은 초 단위로 멈출 수 있어 **수신 시(세션 스레드)** 로 옮겼다. 나중에 마운트된 NAS는 다음 복사부터 반영된다.
4. **원격 파일 *내용*** 은 여전히 설계만(DR-30 · docs/26 · T-31c) — 이번 것은 DR-6 "경로 목록"의 완성이다.
