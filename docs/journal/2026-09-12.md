### 자동으로 못 한 것 → 실기(T-31c · [21 §6 S16~S21](../21-manual-test.md))

두 기기 세션에서의 실제 전송(펌프→세션→서빙→디스크)·패널·트레이·알림은 GUI 두 인스턴스가 필요하다. 관리자 루프백 테스트가 세션 소켓만 뺀 같은 경로를 돌리지만 **실기 확인 전까지 "동작한다"고 말하지 않는다**.

### 한계 · 후속

1. **팝업**엔 배지가 없다(메인창만) — 팝업에서 원격 항목을 고르면 트레이 알림 "받는 중"으로만 안다.
2. 실재 확인·캐시 stat은 세션/펌프 스레드, UI는 메모된 결과만 본다(DR-41) — 단 `item_status`의 **첫 stat**은 UI 스레드(로컬 캐시 디렉터리 · 열쇠당 1회).
3. 원본이 **바뀐** 파일은 실패로 두고 자동 재시작하지 않는다(사용자가 다시 복사해야 새 약속이 온다).
4. `IDataObject` 지연 렌더링(붙여넣는 순간 스트리밍)은 채택하지 않았다 — 필요해지면 캐시 위에 얹는다(DR-43).

### 한계 · 후속(T-51)

1. **mac 다중 파일 게시는 실기 미확인** — `public.file-url`은 타입 하나에 URL 하나라 legacy `NSFilenamesPboardType`(XML plist)을 함께 낸다. 못 읽어도 **경로 텍스트는 항상 함께 게시**되므로 조용히 실패하지는 않는다.
2. **목록 UI 배지 미구현** — docs/08 §3-2의 *"`⚠` 이 PC에 없음 / `✅` 접근 가능"* 행별 표시. 지금은 **로그**로만 알린다.
3. **실재 확인은 수신 시 1회** — docs/08 P-1의 문자 그대로는 *"붙여넣기 직전"* 이지만, 붙여넣기는 UI 스레드에서 일어나고 끊긴 UNC 경로 확인은 초 단위로 멈출 수 있어 **수신 시(세션 스레드)** 로 옮겼다. 나중에 마운트된 NAS는 다음 복사부터 반영된다.
4. **원격 파일 *내용*** 은 여전히 설계만(DR-30 · docs/26 · T-31c) — 이번 것은 DR-6 "경로 목록"의 완성이다.
