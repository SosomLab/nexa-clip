### ③ choco guard 결함(원인 · 협업 세션 확인)

- guard는 `api/v2/Packages()?$filter=Id eq <pkg> and Version eq <직전>` 응답에 `<entry>`가 있으면 "공개됨"으로 보는데, 이 API는 **승인 전 패키지도 돌려준다** — 10-04 확인: `nexa-clip`·`nexa-clip-portable` 0.1.5 둘 다 entry 1 · `IsApproved=false` · `PackageStatus=Submitted`. → guard가 0.1.5를 공개된 것으로 오판해 0.1.6 push를 시도 → Chocolatey가 **403 (Forbidden)** 으로 거부(0.1.5 검수 중이라 새 버전 거부로 추정 · 응답 본문은 로그에 없음).
- 즉 [packaging/README](../../packaging/README.md) 검수 대기 표의 전제 *"모더레이션 중 패키지는 피드에 숨는다"* 가 **틀렸다**(적어도 Id+Version 필터에서는).
- 수정안(소스 = 개발 세션 결정): 판정을 `<entry>` 유무 대신 `<d:IsApproved m:type="Edm.Boolean">true` 유무로(`publish-windows-packages.yml` 101행 부근).
- **두 조회의 차이가 오판의 뿌리**: Id만으로 조회하면 미승인은 안 나온다(오늘 낮 점검의 "피드 등재 0"은 그 조회) · guard는 Id+Version으로 조회해 미승인도 걸렸다.
- ✅ **수정(개발 세션 · `.github/workflows/publish-windows-packages.yml`)**: 판정 = `<d:IsApproved m:type="Edm.Boolean">true` 유무 · 단계 이름 "직전 버전이 승인됐는가" · 머리 주석 표의 choco 줄도 같은 뜻. 대조: clip 0.1.5 두 패키지 = 미승인 → **skip**(음성) · nexa-beep 0.2.2 = 승인 → **go**(양성). 0.1.6 조회 = entry 0(제출 안 됨 확인).

## 9차(win) — ⑧ Excel 셀 범위 그림 정책 재수정 · ⑨ "이미지로 복사" = 원본 그림 · ⑩ 이력에서 고른 Excel 항목 그림 게시 · 설치본 교체 (사용자 10-04 "추천 구현" · ⏸ 배포는 중지 상태 그대로)

### ① 무엇을 · 왜

- **문제**: 7차 ①("셀 범위면 그림을 전혀 안 받음")이 과해 **일반 범위의 Excel 그림까지 잃었다** — 사용자 스크린샷: "이미지로 복사"가 글로 다시 그린 그림이 됨.
- **새 정책**(`nclip_core::capture::cell_range_dims` · `skip_render(names, fmt, link)` · 상수 `CELL_PICTURE_MAX_*`): Excel `Link` 표현(범위 주소 R1C1 글자 · 청해도 그리지 않음)을 **먼저** 읽어 →

| 범위 | 그림 표현 |
| --- | --- |
| 상한 이내의 일반 범위(행 ≤ **200** · 열 ≤ **50** · 셀 ≤ **5,000**) | 벡터 그림 `CF_ENHMETAFILE` **하나만** 청함 |
| 행/열 전체 · 상한 초과 · `Link` 없음/해석 실패 | 그림 없음(7차 ①과 같음) |
| 비트맵(`CF_DIB` 등) | **언제나 안 청함**(수백 MB 위험) |

- 바뀐 소스: `crates/nclip-core/src/capture.rs` · `crates/nclip-plat/src/watch_win.rs` · 테스트 `cell_range_dims_reads_link_item` · `cell_range_picture_policy`.
- ⚠️ **미확정**: `Link`의 실제 내용(R1C1 꼴 · 행/열 전체 표기 · 저장 안 한 통합 문서에서의 유무)은 개발 세션의 지식 기반 — 이 PC Excel로 확인 못 함. 틀리면 결과는 "그림 없음"(안전한 쪽)이라 오류 대화상자는 다시 안 뜬다. 설치본은 `NEXA_CLIP_DIAG` 없이 뜨므로 확인은 사용자 실기.

### ①-2 ⑨ "이미지로 복사"가 복사 때 받은 원본 그림을 쓴다(사용자 10-04)

- **문제**: `Shell::copy_as_image`가 **항상 HTML 런을 직접 다시 그림** — Excel 범위·PPT 글상자는 앱이 그린 그림(벡터 EMF · PNG)이 함께 오는데도 쓰지 않아 표 선·셀 색·병합이 사라진 "글로 그린 그림"이 나왔다(사용자 스크린샷).
- **수정**(`crates/nexa-clip/src/tray_cmd.rs`): 먼저 `decode_image(item.reps, 4096)`(섬네일과 같은 순위 PNG → DIB → EMF)로 **원본 그림**을 쓰고, 그림이 없는 항목만 종전대로 직접 렌더. ⑧(Excel 범위에서 EMF를 받음)과 한 쌍. EMF 가지는 `cfg(windows)`.
- ⏳ 사용자 Excel 실기 — 일반 범위 복사 → 이미지로 복사 → Excel 모양 그대로인지.

### ①-3 ⑩ 이력에서 고른 Excel 항목을 그림판에 붙이면 아무 일도 없음(사용자 실기 17:23 스크린샷)

- **증상**: Excel 복사 직후 그림판 붙여넣기는 그림으로 되는데, 이력에서 그 항목을 골라 붙이면 그림판에 아무 일도 없다.

- ⚠️ **미확정**: 실제 Excel 왕복은 사용자 실기로만 확인 가능 — 전제 = ⑧의 `Link` 해석이 맞아 EMF가 이력에 들어 있어야 함 · **17:23 이전에 복사한 항목은 EMF가 없어 여전히 안 됨 → 새로 복사해야 함**.

- **D. 반려 뒤 재제출은 같은 버전으로** — `publish-windows-packages`는 **기본 브랜치의 `packaging/`** 을 쓴다(체크아웃에 ref 없음 · 자산만 태그에서 받음) → 수정이 main에 push된 **뒤** `tag=v0.1.5 force=true`로 실행 · 그 실행 동안 `WINGET_PUBLISH=false`(force가 winget guard도 무시) → 끝나면 `true` 복구.
