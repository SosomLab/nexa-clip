## 1차(macOS) — ★ 수신 이미지가 "[이미지]"로만 — 팔레트 PNG 디코드 거부 (사용자 실기)

**제보**: Windows에서 전파된 이미지(⇄ kiros33@win · 1222×106)가 목록·미리보기에 섬네일 없이 라벨만. 로컬 이미지는 정상.

| 축 | 내용 |
|---|---|
| 진단 | `nclip-store` 예제 **`dump_item`** 신설(라벨 부분 일치 → 표현·blob 바이트 파일로) → 저장된 표현 = `public.png` 4598B, `file` 판정 **8-bit colormap**(팔레트) |
| 근인 | `nclip-imgdec::decode_png` — `ColorType::Indexed => return None`(팔레트 거부). Windows는 CF_DIB가 함께 있어 가려졌고, 원격 수신(mac `public.png` 한 표현)에서 드러남 |
| 수정 | `png::Transformations::EXPAND \| STRIP_16` — 팔레트→RGB(A)(tRNS→알파) · 저비트 그레이 확장 · 16→8비트. 회귀 테스트(팔레트 PNG 인코드→디코드 RGBA 단언) |
| 검증 도구 | `nclip-plat` 예제 **`decode_probe`**(3-OS · 파일 → 격리 워커 디코드). 실제 바이트 384×33 ✓ · 설치된 워커로도 ✓ |
| 함정 | `cargo build --example …`을 `-p nclip-imgdec`와 함께 주면 **bin 타깃이 안 만들어진다** — 낡은 워커를 복사해 첫 검증이 헛돌았다(산출물 시각으로 발견) |

**실측**: clippy 0 · 20 스위트(+1) · 설치본 교체.

**회신 2(사용자: 미리보기 ✓ · 섬네일 ✗ · 수신 표시 사라짐)**:
- 섬네일 ✗ = `pump_thumbs`가 RAM 섬네일/blob 참조 없는 항목을 영구 `fail` — 캡처 때 생성 실패분(옛 워커·팔레트)은 자가 복구 불가
  → ★ **자가 치유**: 이미지 계열이면 본문 표현에서 `decode_image`로 만들어 표시 + `encode_raw_isolated` → `ThumbEncoded`(마이그레이션 경로)로 PNG blob 영속.
- 수신 표시 사라짐 = **결함 아님** — 제 디코드 검증(`osascript set the clipboard … PNGf`)이 같은 PNG를 mac 클립보드에 올려
  **로컬 항목(#69 · 출처 Code)** 으로 캡처됐고, 중복 제외(로컬 우선)가 수신본(#66 · ⇄)과 한 행으로 합쳐 대표를 로컬로 바꿈(덤프로 확인).
  공유 대상·승인과 무관. 중복 제외를 끄면 두 행(수신본 = 녹색 점)이 보인다.
