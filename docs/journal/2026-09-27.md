### ② 근인 — 09-05 완화(`4e52c4e`)가 놓친 갈래

사용자 단축키 = `key.open=Shift+Alt+C`(포털 GlobalShortcuts). 09-05 분석은 "포커스 때 합성 Pressed + X 오토리피트"까지였고 처방은 ⓐ `is_synthetic` 버림 ⓑ **첫 진짜 누름 전** repeat 버림 ⓒ 유예를 `Focused(true)`부터. 그런데 사용자 증상은 **손을 다 뗀 뒤에도 무한** — 리피트가 아니라 **키가 서버에 고착**된 것이다. 코드만으로는 못 가르므로 **사람 없이 재현하는 하네스**를 만들어 X 서버 사실을 찍었다(아래 ③).

winit X11의 repeat 판정은 **소프트웨어**(`held_key_press == keycode`)라 포커스 뒤 **첫 KeyPress는 `repeat: false`** — 그래서 ⓑ의 `fresh_press`가 그 첫 리피트에 켜지고 이후 리피트가 전부 검색창으로 흘렀다(150ms 유예는 첫 것만 걸렀다).

### ③ ★ 자동 재현 — `scripts/linux-keyprobe`(신설)

포털 RemoteDesktop으로 `Shift↓ Alt↓ C↓`를 넣고 유지·해제 순서를 바꾸며 **XI2 raw 키 이벤트**(서버가 처리한 모든 누름/뗌) + **`QueryKeymap`**(서버가 눌렸다고 믿는 키) + 팝업 스크린샷을 기록. ⚠️ 포털은 cgroup에서 앱 id를 읽으므로 **`app-gnome-nexa\x2dclip-*.scope`** 안에서 띄워야 한다(에디터 셸 그대로 = `com.microsoft.VSCode`로 잡혀 승인 대화창 대기 — 첫 시도가 여기서 멈췄다 · 토큰 파일은 무사).

### ④ 수정 1차(실패) → ★ 앱 계측이 뒤집은 전제 → 수정 2차

**1차**: `keys::FocusResidue` — "포커스 때 winit이 올리는 **합성 Pressed 집합**(이미 눌려 있던 키)은 해제까지 입력이 아니다". 단위 테스트는 통과했지만 **하네스 재실행에서 스톰 그대로**. `xev`·raw 로거로는 앱이 받는 이벤트를 볼 수 없어(XKB 오토리피트는 raw 이벤트가 없고 창의 KeyPress도 xev에 안 보였다) **앱 자체 계측**을 넣었다 — `NEXA_CLIP_KEYDIAG=1`이면 팝업의 `KeyboardInput`·`Ime`·프로브를 stdout에 전부 찍는다(release 바이너리를 앱 스코프로 띄워 설치본과 같은 조건).
