# 03 · 경쟁 프로그램 조사 — OS별 클립보드 매니저 · 장단점 · 크로스플랫폼

> **목적**: 클립보드 매니저를 **운영체제별로 전수 조사**해 기능 기준선과 실패 사례를 뽑고,
> **크로스플랫폼 제품은 별도 섹션([§5](#5-크로스플랫폼-제품--별도-분석))** 으로 분리해
> 우리 개발 방향(자체 렌더 · 단일 바이너리)의 근거로 삼는다.
> 재발명 금지 원칙(`nexa-beep` `docs/16 §2-7`)의 실행 문서.
>
> **조사일: 2026-08-25** · 출처는 [§7](#7-출처). 1차 출처(공식 사이트·저장소)를 우선하고,
> 확인하지 못한 항목은 **"미확인"** 으로 남긴다(추정 금지).

## 1. 조사 범위와 분류

클립보드 매니저는 "복사 기록을 쌓아 다시 붙여넣는다"는 한 줄 기능처럼 보이지만, **OS마다 클립보드의 구조 자체가 달라** 제품 성격이 갈린다. 그래서 아래 4계층으로 나눠 조사했다.

| 계층 | 정의 | 우리와의 관계 |
|---|---|---|
| **A. OS 내장** | OS가 기본 제공하는 클립보드 기록 | ★ **경쟁의 하한선** — 이걸 못 넘으면 설치 이유가 없다 |
| **B. OS 전용 서드파티** | 한 OS에서만 도는 전문 제품 | ★ 기능 기준선을 여기서 뽑는다 |
| **C. 크로스플랫폼** | 2개 이상 OS 지원 | ★★ [§5](#5-크로스플랫폼-제품--별도-분석) — **우리와 직접 경쟁** |
| **D. 런처 내장** | 런처·자동화 도구의 부속 기능 | 번들링 압력의 출처(단독 제품이 밀리는 이유) |

### 1-1. 먼저 알아야 할 것 — OS별 클립보드 구조 차이

이 차이가 **제품 설계와 난이도를 전부 결정한다.**

| OS | 저장 모델 | 변경 감지 | 구조적 함정 |
|---|---|---|---|
| **Windows** | **OS가 데이터를 보관**(글로벌 메모리) — 복사한 앱이 죽어도 남는다 | `AddClipboardFormatListener` → `WM_CLIPBOARDUPDATE` **이벤트** | 클립보드는 **전역 잠금** — `OpenClipboard` 실패·경합이 일상. 지연 렌더링(요구 시 데이터 생성) 처리 필요 |
| **macOS** | `NSPasteboard`가 보관 | ★ **이벤트 없음** — `changeCount` **폴링**이 유일한 공식 수단 | 폴링 주기 = 배터리 vs 누락의 트레이드오프. 자동 붙여넣기는 **손쉬운 사용(Accessibility) 권한** 필수 |
| **Linux / X11** | ★ **OS가 안 갖는다** — **복사한 창이 소유자**로서 계속 들고 있다 | `XFIXES` 셀렉션 알림 | **창을 닫으면 클립보드가 사라진다** → 매니저가 "선택 사항"이 아니라 **사실상 필수** |
| **Linux / Wayland** | 컴포지터가 중개 · 앱끼리는 서로 못 본다 | `wlr-data-control` / `ext-data-control` 프로토콜 | ★ **프로토콜 미지원 컴포지터(GNOME/Mutter)에서는 기록 수집 자체가 불가** — 제품 지원 범위가 데스크톱 환경에 갈린다 |

> ★ **이 표 하나가 [§5](#5-크로스플랫폼-제품--별도-분석)의 결론을 예고한다** — 크로스플랫폼이 어려운 진짜 이유는 UI가 아니라 **캡처 계층의 모델이 서로 다르다는 것**이다.

**장점** — 설치 0 · OS 통합 · 클라우드 동기화 무료 · 샌드박스로 안전.
**단점** — ★ **25개 상한**이 결정적(반나절이면 밀려난다) · **검색 없음**(스크롤만) · **파일 미지원** · 고정 외 영속 없음 · 분류/태그/변환 없음 · 팝업 위치·크기 고정.

> 👉 **Windows 서드파티 시장이 죽지 않는 이유가 이 표에 다 있다.** 우리 기준선은 "Win+V보다 나은가"가 아니라 **"25개·무검색·무파일을 어떻게 넘는가"** 다.

## 3. macOS

### 3-A. 내장 — ★ **없다**

macOS에는 **클립보드 기록 기능이 아예 없다.** 기본 제공은 다음 둘뿐이고 **둘 다 기록이 아니다.**

| 기능 | 실체 |
|---|---|
| **Universal Clipboard** | 기기 간 **현재 항목 1개** 공유(Handoff) — 기록이 아니다 |
| Finder 편집 메뉴 → "클립보드 보기" | **현재 항목 1개 미리보기** — 기록이 아니다 |

> 👉 **그래서 macOS는 이 카테고리의 시장이 가장 크고 유료화가 가장 잘 된다.** 사용자가 *"없으면 못 산다"* 고 말하는 유일한 OS.

## 4. Linux

### 4-A. 구조 — 매니저가 **선택이 아니라 필수**

X11에서 클립보드는 **OS가 아니라 복사한 애플리케이션이 소유**한다. 그래서 **그 창을 닫는 순간 붙여넣을 것이 사라진다.** 데스크톱 환경들이 매니저를 기본 탑재하는 이유가 이것이다.

Wayland는 컴포지터가 중개하지만, **기록 수집에는 `wlr-data-control`(또는 `ext-data-control`) 프로토콜이 필요**하고 **GNOME(Mutter)은 이를 지원하지 않는다.** → ★ **같은 Linux인데 데스크톱 환경에 따라 제품이 아예 못 돈다.**

### 5-4. ★ 사용자 실사용 기준선 — Maccy(macOS) + CopyQ(Windows)

## 6. 종합 — 시장 공백과 우리의 위치

### 6-1. 조사에서 나온 사실 5개

1. **OS 내장은 어디도 충분하지 않다.** Windows는 25개 상한·무검색·무파일, **macOS는 아예 없고**, Linux는 환경마다 다르다.
2. **한 OS를 벗어나면 선택지가 급감한다.** 성숙한 크로스플랫폼은 **CopyQ 하나**, 현대적인 건 **EcoPaste·PasteBar(둘 다 Tauri)** 뿐이다.
3. ★ **크로스플랫폼 제품 전부가 "프레임워크 룩"을 판다.** CopyQ는 Qt 위젯, EcoPaste·PasteBar는 OS WebView — **OS마다 다르게 보이고, 어느 OS에서도 그 OS 같지 않다.**
4. ★ **암호화를 기본값으로 켜 두는 제품이 하나도 없다.** *(2026-08-25 정정 — 초판은 "암호화하는 제품이 하나도 없다"고 썼으나 **CopyQ 14.0.0의 내장 at-rest 암호화**를 누락했다. 다만 **옵트인**이고 **내보내기 경로는 암호화되지 않는다**.)* 클립보드는 **비밀번호·API 토큰·주민번호가 매일 지나가는 통로**인데, 대부분의 제품에서 기록은 평문으로 디스크에 눕는다.
5. **무게가 생사를 가른다.** 이 카테고리는 24시간 상주다. Electron 제품(1Clipboard)은 그래서 죽었고, Maccy는 그래서 산다.

### 6-2. Nexa Clip의 자리 — 세 개의 차별점

| # | 차별점 | 근거 |
|---|---|---|
| **① 3-OS 완전 동일 화면** | **자체 CPU 래스터라이저로 직접 그린다**(`nexa-beep` ADR-0001 계승) — Qt도 WebView도 쓰지 않는다. **스크린샷으로 OS를 구분할 수 없게** 한다. 원칙은 `nexa-beep` `docs/14 §1` — *"보이는 것은 한 벌, 손에 익는 것은 그 OS"*(시각=통일 · 동작 관례=각 OS 네이티브) | [§5-3](#5-3-기능-매트릭스--채택-결정표) 마지막 행 = **0/6** |
| **② 기기 간 동기화가 기본 기능 + 전송 구간 E2E** | ★ **경쟁 제품 중 P2P·E2E 동기화를 기본 제공하는 곳이 없다** — Win+V/Paste는 **클라우드 계정**, Ditto는 LAN이지만 암호화 보증이 약하다. 우리는 **서버가 내용을 못 보고**(봉투 원리) **다른 `UserId`에게 새지 않는다**(DeviceList 검증). ⚠️ *정정 08-26*: 초판의 "암호화가 기본값"은 **로컬 디스크** 기준이었으나, [DR-20](10-decision-record.md)으로 **투자 우선순위를 네트워크로 확정**했다 — 로컬 암호화는 선택이다 | [§5-3](#5-3-기능-매트릭스--채택-결정표) 동기화 행 · [DR-19](10-decision-record.md)·[DR-20](10-decision-record.md) |
| **③ 상주 예산 게이트** | 유휴 RSS·바이너리 크기에 **CI 게이트**를 걸어 Maccy급 가벼움을 크로스플랫폼에서 달성(`nexa-dir2` DR-2 계승) | 1Clipboard의 사망 원인 |

> **한 줄 정리** — *"Ditto의 능력 · Maccy의 가벼움 · CopyQ의 이식성을, 프레임워크 없이 우리가 그린 한 벌의 화면으로."*

### 6-3. 반면교사 3개

| 사례 | 교훈 |
|---|---|
| **1Clipboard**(Electron · 중단) | 상주 앱에 무거운 런타임을 얹으면 기능과 무관하게 죽는다 |
| **Parcellite · ClipIt · Clipy**(정체) | 텍스트 전용 + 유지보수 정체 = 조용한 퇴장. **포맷 확장성**이 곧 수명이다 |
| **Wayland/GNOME 캡처 불가** | 플랫폼 계층을 **포트로 격리**하지 않으면 환경 하나가 제품 전체를 막는다 → `plat` 크레이트 경계가 필수 |
