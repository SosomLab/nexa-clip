# 21 · 실기 점검표 — Windows · macOS · Linux 각각

> **역할**: ★ **OS별로 무엇이 검증됐고 무엇이 안 됐는지**를 한 장에서 관리한다.
> 사용자 방침(2026-08-26): *"맥 버전에 대한 테스트는 맥에서 점검 요청을 할 테니, 기능에 대한 검증을 Windows·macOS 각각 확인할 수 있도록 관리해줘."*
>
> ★ **자동 테스트가 못 잡는 것만 여기 있다.** 순수 로직은 `cargo test`가 잡고([docs/20 §7](20-implementation-spec.md)),
> **OS 권한·포커스·클립보드·트레이처럼 사람이 눈으로 봐야 하는 것**이 이 문서의 대상이다.
>
> **갱신 규칙**: 점검한 사람이 **날짜·버전·결과**를 채운다. 실패는 지우지 말고 **증상을 그대로** 남긴다.

## 1-1. ★ T-12d7 — 고DPI 배율 (Retina) · 08-27 수정

### 증상 (사용자 제보 · macOS 스크린샷)

설정 창에서 **레이아웃은 정상 크기인데 글자만 깨알**로 보였다 — 행 높이·사이드바 폭·여백은
2배로 커졌는데 텍스트만 1배로 남은 상태.

### 원인

`RasterCtx`는 배율을 **글자 크기에 곱해** 그린다. 그런데 호스트가 그 값을 넘기지 않았다.

```rust
// 잘못된 코드 — 배율이 기본값 1.0으로 남는다
let mut dc = RasterCtx::new(&mut gfx, &self.font);
```

위젯에는 `set_scale(2.0)` 을 줬으므로 **레이아웃만 2배**가 됐다.
⚠️ **Windows(배율 1.0)에서는 우연히 맞아 보인다** — 그래서 한쪽 OS에서만 조용히 틀렸다.
`nexa-beep`는 같은 자리에서 `.with_scale(entry.scale)` 을 호출하고 있었다(`app.rs:14055`).

### 조치 — ★ 테스트가 아니라 **구조**로 막았다

`RasterCtx::new(surface, font, **scale**)` — 배율을 **필수 인자**로 승격했다.
빌더 옵션이면 또 빠뜨릴 수 있지만 인자는 **컴파일러가 강제**한다.

### 재점검 (macOS)

| # | 확인 |
|:--:|---|
| 1 | `cargo run -p nexa-clip -- settings` — 글자 크기가 행 높이에 **맞아 보이는가** |
| 2 | 창을 **Retina ↔ 외부 모니터** 로 끌어 옮겨도 즉시 맞는가(`ScaleFactorChanged`) |
| 3 | `cargo run -p nexa-clip -- demo` — 같은지 |

## 2. T-9b · K-1 — 포커스 복원 + 키 주입

> ★ **제품의 존재 이유가 걸린 검증**이다. 이 왕복이 안 되면 "선택하면 붙여넣어진다"가 성립하지 않는다.
> 창을 만들기 전에 먼저 검증한다([docs/02 K-1](02-roadmap.md#7-리스크--일정을-실제로-흔들-것)).

### 2-1. 절차 (3-OS 공통)

```bash
cargo run -p nexa-clip -- spike-paste          # 원본 붙여넣기 경로
cargo run -p nexa-clip -- spike-paste --plain  # 평문 붙여넣기 경로
cargo run -p nexa-clip -- spike-paste --wait 8 # 대상 고를 시간 늘리기
```

1. **아무 텍스트나 복사**해 둔다(`Ctrl+C` / `⌘C`).
2. 붙여넣을 앱(메모장 · TextEdit · 편집기)을 열고 **커서를 둔다**.
3. 스파이크를 실행하고, 카운트다운 동안 **그 앱을 클릭**해 포그라운드로 만든다.
4. 카운트다운이 끝나면 프로그램이 **포커스를 뺏었다가**(팝업이 뜨는 순간을 흉내) **되돌리고 붙여넣기 키를 넣는다**.
5. ★ **대상 앱에 텍스트가 들어갔는지 눈으로 확인**한다.

### 2-2. 판정

| 관찰 | 판정 |
|---|---|
| 대상 앱에 텍스트가 들어갔다 | ✅ **통과** |
| `[5] 포커스 복원: ok` 인데 붙여넣기가 안 됐다 | ❌ 주입 실패 — 키 코드·수식 키 문제 |
| 창이 **깜빡이기만** 하고 포커스가 안 갔다 | ❌ 복원 실패 — Windows면 `AttachThreadInput` 경로 확인 |
| `권한 필요` 가 떴다 | ⏸ macOS 손쉬운 사용 허용 후 재시도([§2-4](#2-4-macos--점검-요청)) |

### 2-3. Windows — ✅ 통과 (2026-08-26)

| 항목 | 값 |
|---|---|
| 점검일 · 버전 | 2026-08-26 · `0.1.0` |
| 환경 | Windows 11 Pro 26200 |
| `capability` | `Full { backend: "win32-sendinput" }` |
| **키 주입** | ✅ **실사용 통과** — 사용자가 Sublime Text 대상으로 붙여넣기 성공 확인 |
| **포커스 복원** | ⚠️ ★ **미검증** — 아래 참조 |

**⚠️ 실행에서 `[3] 포커스 탈취: 실패` 가 떴다**(Windows Terminal에서 `GetConsoleWindow`가 안 잡힘).

```
[2] 대상 기억 : … - Sublime Text …
[3] 포커스 탈취: 실패
[5] 포커스 복원: ok
[6] 키 주입    : ok (Original)
→ 붙여넣기 성공
```

★ **탈취가 실패했다는 것은 대상이 계속 포그라운드로 남았다는 뜻**이다. 그러면 `SetForegroundWindow`는
사실상 할 일이 없었고, **`AttachThreadInput` 우회 경로는 실행되지 않았다.**
따라서 이 실행이 증명한 것은 **키 주입까지**이고, **복원은 아직 미검증**이다.

**조치(08-26)**: 콘솔 창을 못 잡으면 **임시 최상위 창을 잠깐 띄워** 진짜로 포커스를 가져오도록 스파이크를
고쳤다. 다시 돌려서 `[3] 포커스 탈취: ok` 가 뜬 상태로 붙여넣기가 되면 그때 복원까지 통과다.

**재검증(08-27)**: ✅ **통과** — 사용자 실기로 탈취 경로가 실행된 상태에서 붙여넣기 확인
(출력 미첨부 · 문제 재발 시 출력 첨부 요청).

**구현 메모** — `SetForegroundWindow`는 아무 프로세스나 부를 수 없다(포그라운드 강탈 방지).
우리 스레드를 대상 창의 입력 큐에 **붙였다 떼는**(`AttachThreadInput`) 우회가 필요하고,
**없으면 창이 깜빡이기만 한다**. `INPUT` 구조체 크기(x64에서 40B)가 틀리면 `SendInput`이
조용히 0을 돌려주므로 **컴파일 시점 `assert!`** 로 잠갔다.

> 🔴 **남은 실사용 확인**: 실제 붙여넣기가 대상 앱에 들어가는지 **사람이 눈으로** 봐야 한다
> (위 절차 5번). 자동 점검은 `capability`까지만 본다.

## 2-7. T-14b Linux — 유형별 **자동** 실기

> ★ Windows·macOS는 사람이 앱에서 복사해 눈으로 봤다. Linux는 클립보드에 유형을 직접
> 쓸 수 있어(`wl-copy --type`) **하네스로 자동화했다** — 사람 없이 재현된다.

```bash
bash scripts/linux-watch-e2e.sh                          # Wayland — 빌드 → watch 기동 → 8유형 주입 → 로그
NCLIP_E2E_X11=1 bash scripts/linux-watch-e2e.sh          # X11 — WAYLAND_DISPLAY 지우고 xclip 주입(XWayland)
NCLIP_E2E_X11=1 NCLIP_E2E_XVFB=1 bash scripts/linux-watch-e2e.sh  # 순수 X11 — Xvfb :99(데스크톱 클립보드 무관)
```

⚠️ **클립보드를 덮어쓴다** — 복사해 둔 것이 있으면 먼저 붙여 넣을 것.
환경 준비는 [18 §9](18-build-and-test.md#9-linux-환경--배포판별-차이-포함).

### 통과 기준 — 8유형

| # | 유형 | 기대 | 08-29 실측(Ubuntu 26.04 · GNOME/Wayland) |
|:--:|---|---|---|
| 1 | 텍스트(한글) | `Text` · 미리보기 정상 | ✅ `한글 텍스트 테스트` |
| 2 | HTML | `RichText` | ✅ `text/plain`+`text/html` |
| 3 | RTF | `RichText` | ✅ `text/plain`+`text/rtf` |
| 4 | PNG | `Image` + **치수** | ✅ `[이미지] 256×256` |
| 5 | 파일 1개(한글 이름) | `Files` · 파일명 미리보기 | ✅ `한글검증_v1.0.txt` |
| 6 | 파일 여러 개 | `Files` · `외 N개` | ✅ `한글검증_v1.0.txt 외 1개` |
| 7 | ★ **파일 잘라내기**(`x-special/gnome-copied-files`) | `Files` — **벤더로 새면 안 된다** | ✅ `Files` · 첫 줄 `cut` 제외 |
| 8 | 민감 표식(`x-kde-passwordManagerHint`) | 내용 없이 거부 | ✅ (아래 ⚠️) |

⚠️ **8번은 `watch`가 아니라 `peek`으로 본다.** 표식 항목은 plat 게이트
([`WatchGate::admit`](../crates/nclip-plat/src/watch.rs))가 **가장 이른 지점에서** 버리므로
`watch` 목록에는 줄로도 남지 않는다(fail-closed — 의도된 동작). 확인은 이렇게 한다:

```bash
printf 'secret' | wl-copy --type x-kde-passwordManagerHint
cargo run -p nexa-clip -- peek          # → "(민감 표식 — 기록하지 않습니다)"
```

★ `NEXA_CLIP_DIAG=1`이면 `watch`에서도 `[diag] 변화 감지 — 표현 0개 · 표식 true`로
**이벤트가 왔다는 사실**은 보인다 — *"막혀서 안 보인다"* 와 *"놓쳤다"* 를 구분하는 자리다.

### 거부 경로도 함께 본다 — 조용한 실패 금지

```bash
env PATH=/usr/bin:/bin cargo run -p nexa-clip -- watch          # → MissingTool + 배포판별 설치 안내
env -u WAYLAND_DISPLAY -u DISPLAY cargo run -p nexa-clip -- peek # → NoDisplayServer + 조치
```

### 08-29 4차 — X11 경로 · 다른 컴포지터 실측

| 환경 | 결과 |
|---|---|
| **X11 · XWayland**(`DISPLAY=:0`, `WAYLAND_DISPLAY` 제거) | ✅ `x11-xclip` 7/7 — Mutter가 X↔Wayland 클립보드를 양방향으로 이어 **직전 Wayland 케이스 8(표식)을 X11 경로가 기동 시 거부**한 것까지 보였다 |
| **X11 · 순수 Xvfb :99**(루트 없이 `apt-get download xvfb`) | ✅ 7/7 + 표식 `peek` 거부 |
| **Weston 14.0.2**(nested · 루트 없이 구성) | ✅ `wayland-wl-paste` — 텍스트·HTML·`gnome-copied-files` 정판정 |
| 빈 클립보드(X11·Wayland 공통) | ⚠️ `peek`가 *"다른 앱이 잡고 있을 수 있습니다"* — Windows 사정을 Linux에 말하던 **거짓 안내 → 수정**(비어 있거나 못 읽음) |

관찰(수정 없음) — `xclip`은 `wl-copy`와 달리 **`text/plain`을 덧붙이지 않아** HTML/RTF 단독 항목이
`미리보기 없음`이 된다. 실제 앱은 거의 항상 평문을 함께 내놓으므로 하네스 주입의 성질이다.
`wayland-info` 실측: **Mutter 50.1·Weston 14.0.2 모두 `wlr`·`ext` data-control 없음**([18 §9-5](18-build-and-test.md#9-5--컴포지터-차이--여기가-linux-클립보드의-핵심)).

### ⏳ 남은 Linux 실기

| 항목 | 왜 자동화로 안 되나 |
|---|---|
| **실제 파일 관리자** | ✅ **Nautilus 실측**(08-29 사용자 — 복사·잘라내기 모두 `Files` · 포털 키 2종 발견 → 곁다리). ⏳ Dolphin·Thunar가 **실제로 내놓는 표현** 확인([18 §9-6](18-build-and-test.md#9-6--파일-관리자--잘라내기복사-표현이-갈린다) 표 갱신). Wayland에는 입력 주입 도구가 없어 사람이 `Ctrl+C` 해야 한다 — 이 PC(Nautilus): 파일 선택 → `Ctrl+C` → `wl-paste --list-types` 와 `nexa-clip peek` |
| **data-control 있는 컴포지터** | KWin·Sway에서 백엔드 선택 + `ext-data-control-v1` 버전 — 이 PC엔 없다(설치는 sudo) |
| **클립보드 매니저 공존** | Klipper·GPaste가 떠 있을 때 셀렉션 주인 교체가 잦은 상황 |

## 3. T-14 · 클립보드 감시 (구현 후)

| OS | 확인할 것 |
|---|---|
| **Windows** | 텍스트·이미지·**파일 복사**가 각각 1건씩 잡히는가 · 같은 것 재복사 시 **새 항목이 아니라 승격**인가 · 다른 앱이 클립보드를 잠갔을 때 **재시도로 회복**하는가 |
| **macOS** | 폴링이 **유휴 시 느려지는가**(배터리) · 놓치는 복사가 없는가 · `changeCount` 변화 없을 때 **읽지 않는가** |
| **Linux/X11** | 복사한 **창을 닫아도** 내용이 남는가(즉시 읽기 확인) |
| **Linux/Wayland** | 지원 컴포지터(Sway/Hyprland)에서 동작 · ★ **GNOME에서 "수집 불가"가 명시**되는가(조용한 빈 목록 금지) |

**공통 — 민감 정보 차단(FR-S-1)**: 1Password·KeePass 등에서 복사한 것이 **기록에 남지 않아야** 한다.
★ 이건 OS별로 표식이 다르므로 **3-OS 각각** 확인한다.

## 7. ★ 리치 표시 회귀 (T-18d · 09-04 사용자 — "기존 기능이 없어지지 않도록")

리치(색·굵기·들여쓰기·이미지)는 **원천 앱이 올린 `HTML Format`/`text/html`을 우리 파서가 푸는 것**이다.
그래서 "평문처럼 보인다"는 두 가지 중 하나 — ① 원천이 HTML을 안 올렸다(앱 결함 아님) ② HTML은 있는데 파서가 못 풀었다.
판정 순서: `nexa-clip peek`(또는 `watch`)으로 표현 목록에 HTML이 있는지 → 있으면 HTML을 파일로 받아
`NCLIP_HTML_FIXTURE=<path> cargo test -p nclip-core dump_fixture -- --ignored --nocapture` 로 파서 출력을 본다.

| # | 원천 | 기대(목록 Ctrl+1 행 · 미리보기 · 팝업) | Win | mac | Linux |
| --- | --- | --- | --- | --- | --- |
| R1 | VSCode 코드 복사 | 색·굵기 · `&nbsp;` 들여쓰기 · 탭 스톱 열맞춤 | ✅ 09-03 | ☐ | ☐ |
| R2 | Sublime 코드 복사 | `pre` 원시 개행 = 줄 · 색 | ✅ 09-03 | ☐ | ☐ |
