# 27 · 케이스별 캡처·표시 설계 — 무엇을 기록하고 무엇을 보여주나

> [12 포맷](12-clipboard-formats.md)이 *"클립보드는 여러 벌이다"* 와 **저장 모델**을 정했다.
> 이 문서는 그 위에서 **실제 네 가지 복사 케이스**가 각각 어떻게 동작하고 어떻게 보여야 하는지를 정한다.
>
> 사용자 질문(08-26) — *"PPT 글상자 2개 / 색·글크기가 적용된 내용 / 이미지 / 파일, 각각 어떻게 동작하고 어떻게 보여줄지."*

---

> ★ **이 문서의 규칙은 구현됐다**(08-26 · T-14a) → [`nclip-core::capture`](../crates/nclip-core/src/capture.rs).
> OS 호출·디코딩·파일 접근이 없는 **순수 함수**라 실제 클립보드 없이 전수 테스트된다.
> 규칙을 바꾸면 **거기 테스트가 먼저 깨진다**.

## 1. 종류 판정 — 순서가 전부다

한 항목에 표현이 10개씩 들어온다. **어떤 순서로 보느냐**가 종류를 정한다.

```
① 파일 목록 표현이 있다                 → Files
② HTML 또는 RTF가 있다                  → RichText
③ 벤더(앱 고유) 포맷이 있다
     ├ 평문이 함께 있다                 → RichText   (Excel 범위 · 글 있는 도형)
     └ 아니면                           → Object     ★ PPT 도형 · 차트
④ 비트맵/메타파일이 있다                → Image      (벤더 없는 순수 그림)
⑤ 그 외                                → Text
```

★ **그리고 내용이 하나도 없으면 항목을 만들지 않는다** —
곁다리만 있거나 표현이 0개면 버린다([§8-2](#8-2--08-27-2차-훑기--ppt-excel-edge-vs-code)).

> ★ **③의 갈래는 08-27 실기에서 나왔다**(초안은 *"벤더면 무조건 Rich"* 였다).
> .NET `System.Drawing.Bitmap`으로 복사한 **순수 그림**이 "서식 있는 글"로 분류됐다.
> **글이 하나도 없는데 리치라고 하면 거짓말**이라, *"글이 딸려 있는가"* 로 가른다.

### ⚠️ 이 순서를 뒤집으면 생기는 사고

| 뒤집으면 | 무슨 일이 나나 |
|---|---|
| **비트맵을 벤더보다 먼저** 본다 | ★ **PPT 도형 복사에도 `CF_DIB`가 들어 있다.** 종류가 `Image`가 되고, 목록에서도 그림으로 보이고, 사용자가 *"그림이네"* 하고 넘긴다. 표현 자체는 남아 있으니 붙여넣기는 살지만 **분류가 틀리면 검색·필터·보관 정책이 전부 틀린다** |
| **HTML만 보고 Rich** 판정 | 브라우저에서 **이미지**를 복사하면 `<img src=…>` 한 줄짜리 HTML이 같이 온다 → 이미지가 "서식 있는 글"로 분류된다 |
| **파일을 나중에** 본다 | 탐색기 복사에도 파일 이름이 담긴 `CF_UNICODETEXT`가 붙는다 → 파일 3개가 "텍스트 3줄"이 된다 |
| **벤더면 무조건 Rich** | ★ 글이 하나도 없는 **그림**이 "서식 있는 글"이 된다(08-27 실기) |

> **④의 "텍스트가 비었다"** 조건은 ⚠️ 완전하지 않다 — 앱에 따라 이미지 복사에 URL 텍스트를 넣는다.
> 애매하면 **`Image`로 두고 붙여넣기는 사다리대로** 간다(보이는 것이 틀려도 붙는 것은 맞다). → **D-59**

## 2. 케이스 ① — PPT에서 글상자 2개

### 2-1. 클립보드에 실제로 들어오는 것

Windows에서 도형 2개를 복사하면 대략 이렇게 들어온다(실측 대상 — [21](21-manual-test.md)에 항목 추가):

| 포맷 | 무엇 | 우리에게 |
|---|---|---|
| `Art::GVML ClipFormat` | Office 도형 XML | ★ **도형을 도형으로 되살리는 유일한 표현** |
| `PowerPoint 14.0 Slides Package` | PPT 내부 | 벤더 |
| `Embed Source` · `Object Descriptor` | OLE | 벤더 |
| `CF_ENHMETAFILE` · `CF_METAFILEPICT` | 벡터 그림 | 미리보기 후보(⚠️ 우리가 렌더 못 함) |
| `CF_DIB` · `CF_DIBV5` | 비트맵 | ★ **미리보기 정답** |
| `CF_HTML` · `Rich Text Format` | 글상자 안 텍스트의 서식본 | 사다리 중간 |
| `CF_UNICODETEXT` | `『세방전지㈜ ERP…』\n요구사항 분석 (MP)` | 사다리 바닥 |

macOS는 이름만 다르다 — `com.microsoft.PowerPoint.drawing` · `public.rtf` · `public.png` · `public.utf8-plain-text`.

### 2-2. 동작

- **기록**: 전부. 대표(`primary`) = 벤더 최상위.
- **종류**: `Rich`, 배지에 **출처 앱**(PowerPoint). ★ *"도형 2개"* 같은 건 **적지 않는다** — 그걸 알려면 GVML을 파싱해야 하고, 그 순간 P-1이 깨진다.
- **붙여넣기(원본)**: 표현 **전부** 재게시. PPT에 붙이면 글상자 2개가 위치·서식 그대로. Word에 붙이면 Word가 자기가 아는 표현을 고른다.
- **붙여넣기(평문)**: `CF_UNICODETEXT` **하나만** 게시.

### 2-3. ★ 미리보기 — 우리가 GVML을 그리지 않아도 되는 이유

**Office가 미리보기용 비트맵을 같은 클립보드에 이미 넣어 준다.** `CF_DIB`를 그대로 쓰면
*"직접 그린다"* 원칙([DR-1](10-decision-record.md))을 깨지 않고 **정확한 미리보기가 공짜로** 나온다.

| 보기 | 그리는 것 |
|---|---|
| **일반** | DIB/PNG 썸네일(가로 맞춤 · 최대 높이 제한) + 출처 배지 |
| **간략** | 작은 썸네일 + 평문 첫 줄 |
| **한 줄** | 평문 첫 줄만 |

⚠️ **EMF만 있고 DIB가 없으면** 우리는 못 그린다(메타파일 인터프리터는 v1 범위 밖).
→ 썸네일 없이 **텍스트 폴백** + `미리보기 없음(EMF)`. ★ **빈 회색 상자만 두고 넘어가지 않는다** — 왜 없는지를 적는다([DR-31](10-decision-record.md) 원인/조치 규칙).

## 3. 케이스 ② — 색·글자 크기가 적용된 텍스트

(형광 배경 + 색 글자 + 굵기가 섞인 문단 — 두 번째 이미지)

### 3-1. 동작

- **기록**: `CF_HTML` · `Rich Text Format` · `CF_UNICODETEXT`(출처가 Office면 벤더 포맷도)
- **종류**: `Rich`
- **붙여넣기(원본)**: 전부 재게시 → 색·크기·하이라이트 유지
- **붙여넣기(평문)**: 텍스트만 → ★ **이 기능이 가장 많이 쓰이는 자리가 여기다**(사용자 필수 요구)

### 3-2. ★ 미리보기 — 무엇을 재현하고 무엇을 버리나

[20 §3-8](20-implementation-spec.md)의 **제한 리치 렌더러**가 그린다.

| 재현한다 | 버린다 |
|---|---|
| 굵기 · 기울임 · 밑줄 | 스크립트 · 이벤트 핸들러 |
| 글자색 · **배경색(하이라이트)** | 외부 이미지·폰트·CSS **네트워크 요청 0** |
| 상대 크기(3~4단계로 스냅) | 절대 위치 · 부동 · 표 병합 |
| 목록 기호 · 표(단순 격자) | 그 밖의 전부 |

★ **원본이 아니라 `CF_HTML`을 파싱한다.** RTF 파서보다 부분집합 HTML 파서가 작고,
우리가 필요한 것(색·굵기·크기·목록)이 **인라인 style로 온다**. RTF는 폴백이 아니라 **붙여넣기용 보관물**일 뿐이다.

⚠️ **못 그리는 태그를 만나면 조용히 무시하지 않는다** — 그 문단을 **평문으로 강등**하고
항목 배지에 `서식 일부 생략`을 붙인다. *"살짝 다르게 그려진 미리보기"* 는
*"미리보기 없음"* 보다 나쁘다(사용자가 붙여넣기 결과를 잘못 예측한다).

| 보기 | 그리는 것 |
|---|---|
| **일반** | 리치 렌더 · 최대 N줄 · 넘치면 아래쪽 페이드 |
| **간략** | 한 줄로 압축하되 ★ **색은 유지** — 이 항목을 알아보는 단서가 색이다 |
| **한 줄** | 평문 |

## 4. 케이스 ③ — 이미지

### 4-1. 동작

- **기록**: 온 바이트를 **그대로** 내용 주소 blob으로. ★ **재인코딩하지 않는다** — 재인코딩은 손실이고 CPU고, 중복 제거(`blob_id = H(내용)`)도 깨진다.
- **정본 선택**: `PNG` > `CF_DIBV5` > `CF_DIB`
  - ⚠️ **`CF_DIB`는 알파를 잃는 일이 잦다** — 32bpp `BITMAPINFOHEADER`의 상위 바이트를 앱마다 다르게 다룬다. PNG가 있으면 PNG가 정본인 이유.
- **종류**: `Image`
- **붙여넣기**: 가진 표현 전부 재게시.

### 4-2. 미리보기

| 보기 | 그리는 것 |
|---|---|
| **일반** | 썸네일(가로 맞춤 · 최대 높이) |
| **간략** | 작은 정사각 썸네일 + `PNG · 1920×1080 · 412 KB` |
| **한 줄** | `[이미지] 1920×1080 PNG` |

썸네일은 **캡처 때 한 번 디코드·축소해서 blob으로 저장**한다(P-3). 목록 스크롤은 축소본만 읽는다.

⚠️ **디코더 범위는 v1에 PNG·BMP·DIB뿐이다.** JPEG·WebP는 **원본은 온전히 보관**하되
미리보기는 `미리보기 없음(JPEG)` 로 정직하게 표시한다. ★ 보관과 표시는 다른 문제다 —
못 그린다고 안 담지 않는다. → **D-60**(디코더 확대 시점)

## 5. 케이스 ④ — 파일

### 5-1. 동작

- **기록**: ★ **경로 목록만**(사용자 확정 — *"파일은 목록만, 내용은 아니다"*).
  Windows `CF_HDROP` · macOS `public.file-url` · X11/Wayland `text/uri-list`.
- **종류**: `Files`
- **붙여넣기**: 경로 목록 재게시 → 탐색기에 붙이면 그때 OS가 복사한다.

### 5-2. ⚠️ 여기에만 있는 함정 두 개

| # | 함정 | 처리 |
|:--:|---|---|
| **F-1** | **잘라내기로 복사된 항목** — Windows는 `Preferred DropEffect`에 *이동* 을 담는다 | ★ **되살릴 때 항상 "복사"로 강등한다.** 히스토리에서 꺼낸 잘라내기가 원본을 지우는 건 **사고**다. 사용자는 3일 전 잘라내기를 기억하지 못한다 |
| **F-2** | **원본 경로가 사라졌다** | 붙여넣기 **직전**이 아니라 **목록에 그릴 때** 확인한다 → 없으면 항목 상태를 바꾸고([DR-31](10-decision-record.md)) 진단 로그에 원인+조치. 모달은 안 띄운다(사용자 확정) |

### 5-3. 미리보기

| 보기 | 그리는 것 |
|---|---|
| **일반** | 확장자 배지 + 이름 최대 5줄 + `외 N개` |
| **간략** | `파일 3개 · report.xlsx 외 2개` |
| **한 줄** | 위와 같음 |

★ **아이콘을 OS 셸에서 가져오지 않는다.** 우리가 그린다 — 확장자 → 색 + 3글자 배지.
셸 아이콘을 쓰면 **3-OS에서 화면이 달라지고**([DR-1](10-decision-record.md)), 아이콘 추출은 OS마다 다른 무거운 API다.

## 6. 저장 구조

```rust
ClipItem {
    id, at_ms, source_app, kind, concealed,
    reps: [ Representation {          // ★ 이름째로 · 해석 없이
        format: "Art::GVML ClipFormat" | "CF_HTML" | "PNG" | "CF_HDROP" | …,
        blob_id,                      // = H(암호문) — 중복 제거·무결성이 같은 규칙에서 나온다
        bytes,
    } ],
    // ⚠️ primary는 **필드가 아니다**(08-26 구현 중 정정) — select_reps가 표현을
    // 버리면 인덱스가 가리키는 자리가 밀린다. ClipItem::primary()로 그때그때 구한다.
    preview: Preview,                 // ★ 목록이 읽는 유일한 것
}

enum Preview {
    Text(String),                     // 첫 N줄
    Rich(String),                     // ★ 캡처 때 한 번 정제된 HTML 부분집합
    Thumb { blob_id, w, h },          // 캡처 때 한 번 디코드·축소
    Files(Vec<String>),               // 이름만(경로 전체는 reps에)
    None { reason: &'static str },    // ★ 왜 없는지를 적는다
}
```

### ★ `preview`를 따로 두는 이유

1. **속도** — 스크롤마다 3MB DIB를 디코드할 수 없다([00 §2](00-vision.md) 검색 ≤16ms 예산)
2. ★ **보안 경계가 한 지점에 모인다** — HTML 정제(스크립트·외부 참조 제거)를 **캡처 때 한 번**만 한다.
   렌더 때마다 정제하면 정제를 빠뜨리는 경로가 언젠가 생긴다
3. **동기화가 싸진다** — 다른 기기에는 preview만 먼저 보내고 원본 표현은 필요할 때([DR-30](10-decision-record.md))

## 7. ⚠️ 용량 — Office 한 번 복사가 20MB다

도형 몇 개 복사에 EMF + DIB + `Embed Source`가 함께 오면 쉽게 수십 MB다.
24시간 상주하며 1,000개를 보관하는 앱에서 이건 그냥 **디스크 폭발**이다.

**규칙**

| # | 규칙 |
|:--:|---|
| **C-1** | **필수 세트는 항상 남긴다** — 대표(벤더 최상위) · HTML · RTF · 평문 · 썸네일 1장 |
| **C-2** | 항목당 상한(설정 · 기본 예 10MB)을 넘으면 **사다리 아래(중복 비트맵·메타파일)부터** 버린다 |
| **C-3** | ★ **버린 것을 항목에 표시한다** — `원본 형식 일부 생략(용량)`. 조용히 버리면 **한 달 뒤 붙여넣기가 이상해지고 이유를 알 수 없다** |
| **C-4** | 같은 blob은 한 번만 저장된다(`blob_id = H(내용)`) — 같은 이미지를 열 번 복사해도 1벌 |

상한 기본값 확정은 → **D-61**

## 8. 붙여넣기 사다리

| 요청 | 게시하는 것 |
|---|---|
| **원본** (기본) | ★ 가진 표현 **전부** — 받는 앱이 고른다 |
| **평문** (⇧ 수식 · 필수 기능) | 평문 하나만 |
| (차후) **서식만** | HTML · RTF · 평문 — 벤더 제외 |

★ **"원본 붙여넣기"는 우리가 최선의 표현을 고르는 기능이 아니다.**
전부 돌려주고 **판단을 받는 앱에 넘기는** 기능이다(P-2).

## 8-1. ★ 08-27 실기(`nexa-clip watch`)에서 드러난 것 넷

설계만으로는 안 보이던 것들이 **첫 실행에서 바로** 나왔다.

| # | 증상 | 원인 | 조치 |
|:--:|---|---|---|
| **①** | `cargo run` 이 `c a r g o   r u n` 으로 찍힘 · **한글은 통째로 사라짐** | ★ `CF_UNICODETEXT`는 **UTF-16LE**인데 UTF-8로 읽었다 | [`decode_plain`](../crates/nclip-core/src/capture.rs) — 포맷별 인코딩 · `plain_rank`로 **정확히 풀리는 것부터** |
| **②** | PowerShell 한 줄 복사가 **RichText**로 분류 | `DataObject`(8바이트 OLE 표식)가 *"모르면 벤더"* 에 걸렸다 | 곁다리 목록에 추가([D-75](#9-이-문서가-여는-결정) 실체화) |
| **③** | 같은 복사가 여전히 RichText | ⚠️ **`CF_OEMTEXT`가 평문 목록에 없었다** — Windows는 텍스트 셋을 함께 올린다 | `is_plain_format`에 추가 |
| **④** | .NET 그림 복사가 **RichText** | *"벤더면 무조건 Rich"* | [§1](#1-종류-판정--순서가-전부다) ③ 갈래 신설 |

★ **넷 다 오류를 내지 않는다**는 게 공통점이다. 조용히 틀린 값이 나오고, 화면을 봐야만 안다.
그래서 [`watch`](../crates/nexa-clip/src/watch_cmd.rs) 가 **저장 경로와 같은 함수**를 쓴다 —
여기서 맞으면 제품에서도 맞다.

⚠️ **`CF_TEXT`·`CF_OEMTEXT`는 시스템 코드 페이지**라 우리가 정확히 못 푼다.
Windows가 텍스트가 있으면 `CF_UNICODETEXT`를 **자동 합성**하므로 그쪽을 먼저 본다 —
순서를 뒤집으면 한글이 깨진다.

## 8-2. ★ 08-27 2차 훑기 — PPT · Excel · Edge · VS Code

사용자가 실제 업무 자료로 **18건**을 훑었다. 결함 셋이 더 나왔다.

| # | 증상 | 원인 | 조치 |
|:--:|---|---|---|
| **⑤** | ★ **PPT 도형이 `Image`** 로 분류 | 08-27 1차의 *"글 없는 벤더 = 그림"* 이 너무 넓었다 | ★ **[`ClipKind::Object`] 신설** |
| **⑥** | PPT 판정이 흔들림 | `JFIF`·`GIF`·`image/svg+xml`이 **그림 목록에 없어** 벤더로 세어졌다 | 그림 포맷에 추가 |
| **⑦** | ★ **표현 0개짜리 항목**이 생김 | Excel이 지연 렌더링으로 다시 채우는 순간에 읽혔다 · rdpclip은 자기 표식만 올린다 | ★ **내용 없으면 항목이 아니다**([`has_content`]) |

### ★ ⑤ — 우리 분류에 **자리가 없었다**

```
[1] 종류: Image · 출처: POWERPNT
    Art::GVML ClipFormat · PowerPoint 12.0 Internal Shapes
    PNG · JFIF · GIF · CF_DIB · CF_DIBV5 …   (평문 없음)
```

PPT 도형은 **이미지도 서식 있는 글도 아니다.**

| 뭐라고 하면 | 왜 틀린가 |
|---|---|
| `Image` | ★ **붙여넣으면 편집 가능한 도형**이라는 사실이 가려진다. 필터로 "이미지"를 고르면 도형이 딸려 온다 |
| `RichText` | 글이 **하나도 없는데** "서식 있는 글"이라고 한다 |

→ **`Object`** 를 새로 뒀다. 미리보기는 함께 온 비트맵을 쓰고, 붙여넣기는 원본을 전부 되돌린다.

★ **경계가 실제로 잘 갈린다** — 같은 훑기에서:

| 실기 | 표현의 특징 | 종류 |
|---|---|:--:|
| PPT 도형 | `Art::GVML` + 그림들, **평문 없음** | `Object` |
| PPT **표** | `Art::Table` + **`HTML Format`** | `RichText` |
| PPT **글상자** | `Art::Text` + HTML + RTF + **평문** | `RichText` |
| **Greenshot** | 진짜 벤더 없음 · `PNG`+`CF_DIB`뿐 | `Image` |

### ⚠️ ⑦ — 빈 항목은 **고장으로 읽힌다**

```
[14] 종류: Text · 출처: EXCEL · 표현: 0개 · 미리보기: 미리보기 없음
[9]  종류: RichText · 출처: rdpclip
     DataObject · Terminal Services Private Data · Ole Private Data
```

목록에 빈 줄이 쌓이면 사용자는 **제품이 고장 났다고 읽는다.**
게이트에서 **민감 표식 바로 다음**으로 걸렀다 — ⚠️ *"다음 1건 무시"* 보다 **앞**이어야 한다.
빈 스냅숏이 예약을 소모해 버리면 **정작 다음 진짜 복사가 저장된다**.

### 실기 회귀 박제

18건을 [`tests/real_clipboard_captures.rs`](../crates/nclip-core/tests/real_clipboard_captures.rs)에
**포맷 이름 그대로** 넣었다. ★ 규칙을 고칠 때 **무엇이 깨지는지 즉시 보인다**.
⚠️ 이름을 보기 좋게 다듬으면 그 순간 실기 기록이 아니라 창작이 된다.
