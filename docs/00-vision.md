# 00 · 비전 — 핵심 편의성과 2026년 흐름

> **역할**: *"클립보드 매니저를 좋게 만드는 것은 무엇인가"* 에 답한다.
> [03 경쟁 조사](03-competitive-landscape.md)가 **누가 무엇을 갖췄나**를 봤다면, 이 문서는 **왜 어떤 것은 잘 쓰이고 어떤 것은 안 쓰이나**를 본다.
> 기능 목록은 [04](04-feature-scope-and-screens.md), 단계별 목표는 [02 로드맵](02-roadmap.md).
>
> 작성 2026-08-25.

## 1. 한 줄

> **Nexa Clip** = *복사한 모든 것을, 세 OS에서 똑같은 화면으로, 암호화해 보관하고, 내 기기 어디서든 한 번에 꺼내 쓰는 상주 도구.*

**누구를 위한 것인가** — 하루에 수십~수백 번 복사·붙여넣기를 하고, **여러 OS를 오가며** 일하는 사람. 개발자·기획자·번역가·운영자.

## 2. ★ 핵심 편의성 8 — 기능이 아니라 **성질**

기능 매트릭스에서 6/6을 받아도 안 쓰이는 제품이 있고, 기능이 적어도 매일 쓰이는 제품(Maccy)이 있다. 차이는 **아래 여덟 가지**에서 난다. **이건 전부 측정 가능해야 한다.**

### ① 호출에서 완료까지 **3초**

클립보드 매니저의 경쟁 상대는 다른 매니저가 아니라 **"그냥 원본을 다시 복사하러 가는 것"** 이다. 그보다 느리면 안 쓴다.

| 항목 | 목표 |
|---|---|
| 단축키 → 팝업 표시 | **≤ 100ms** |
| 타이핑 한 글자 → 목록 갱신 | **≤ 16ms**(1프레임) |
| 전체 조작 수 | **단축키 + 검색어 2~3자 + Enter** |

> ★ 이 하나가 무너지면 나머지 일곱이 다 무의미하다.

### ② 키보드로 완결

손이 마우스로 가는 순간 3초가 깨진다. **팝업 안의 모든 동작에 키가 있어야 한다** — 이동·선택·평문 붙여넣기·고정·삭제·편집·닫기.
Maccy·Ditto·CopyQ가 공통으로 잘하는 것이고, 이 카테고리의 사실상 표준이다.

### ③ 존재를 잊게 하는 상주

24시간 켜져 있는 프로그램이다. **눈에 띄면 이미 실패**다.

| 항목 | 목표 |
|---|---|
| 유휴 RSS | **예산 게이트로 CI에서 강제**(수치는 [ADR-0001에서 확정 예정](02-roadmap.md)) |
| 유휴 CPU | **0%에 수렴** — 폴링은 macOS에서만, 그것도 적응형 |
| 배포 크기 | 단일 실행 파일 |

> ⚠️ **1Clipboard(Electron)가 죽은 이유가 이 항목 하나다.** 기능이 부족해서가 아니었다.

### ④ 눈으로 골라내기

목록이 100줄이면 **읽지 않고 알아봐야** 한다.

- **타입 아이콘**(📄 🖼 📁 🎨) · **한 줄 요약** · **출처 앱** · **상대 시각**
- **미리보기 패널** — 이미지 원본비, 텍스트 전문, 파일 목록, 색상 견본
- Maccy 2.x가 `⌃Space` 슬라이드아웃으로, Paste가 카드 타임라인으로 각각 잘 푼 문제

### ⑤ 위험을 **알아서** 피한다

클립보드에는 비밀번호·API 토큰·주민번호가 매일 지나간다. **사용자가 설정하기 전에** 안전해야 한다.

- OS 민감 표식 존중(비밀번호 관리자가 보내는 *"기록하지 마"*) — **기본 켜짐**
- 제외 앱·패턴 · 자동 만료 · 디스크 봉인
- Maccy가 1Password·KeeWeb·transient 타입을 **스스로 무시**하는 것이 좋은 선례

### ⑥ 실수해도 **되돌아간다**

- 지운 항목 복구 · 덮어쓴 클립보드 복원 · 전체 비우기 확인
- ★ **덮어쓰기 전에 원래 것을 기록에 먼저 넣는다** → 잃는 것이 없다([08 §4-2](08-clipboard-propagation.md#4-2-어느-모드든-지키는-것))

### ⑦ 맥락을 안 깨뜨린다

팝업은 **포커스를 훔치고 반드시 돌려준다.** 붙여넣고 나면 사용자는 **원래 있던 자리 그대로**여야 한다.
⚠️ 이게 [04 §2-1](04-feature-scope-and-screens.md#2-1-s1--퀵-팝업--주-화면)에서 경고한 지점이고, `plat` 계층의 최대 난이도다.

### ⑧ 기기 경계가 **안 느껴진다** (2차 목표)

mac에서 복사한 것이 Windows 팝업에 그냥 있어야 한다. *"동기화됐나?"* 를 생각하게 하면 진 것이다.
→ [08 자동 전파](08-clipboard-propagation.md)

### 2-1. 요약표 — 여덟 성질과 그 반증

| # | 성질 | 무너지면 나타나는 증상 | 잘하는 제품 |
|:--:|---|---|---|
| ① | 3초 안에 끝난다 | *"그냥 다시 복사하는 게 빠르네"* | Maccy · Ditto |
| ② | 키보드 완결 | 손이 마우스로 간다 | Maccy · CopyQ |
| ③ | 잊게 하는 상주 | 팬이 돈다 · 메모리 경고 | Maccy |
| ④ | 눈으로 골라내기 | 목록을 **읽고** 있다 | Paste · Maccy 2.x |
| ⑤ | 알아서 안전 | 비밀번호가 기록에 남는다 | Maccy · GPaste |
| ⑥ | 되돌아간다 | *"방금 그거 날렸다"* | Ditto |
| ⑦ | 맥락 유지 | 붙여넣고 창을 다시 찾는다 | Ditto · CopyQ |
| ⑧ | 기기 경계 없음 | *"그건 저쪽 PC에 있는데"* | Paste(Apple 한정) |

> ★ **①~⑦ 중 하나라도 없으면 나머지를 아무리 잘해도 매일 쓰이지 않는다.**
> 이 표가 [02 로드맵](02-roadmap.md)의 수용 기준 원천이다.

## 3. 2026년 최신 흐름 — 무엇이 새로 표준이 되었나

> 조사일 2026-08-25. 출처는 [§5](#5-출처).

| # | 흐름 | 대표 사례 | 성격 |
|:--:|---|---|---|
| **T-1** | ★ **로컬 OCR — 이미지에서 텍스트 추출** | **PowerToys Advanced Paste**(로컬 OCR) · Maccy 2.x · ClipClip · PasteIt | ★ **사실상 표준화 진행 중**. 중요한 건 **로컬**로 돈다는 점 |
| **T-2** | **AI 변환**(요약·번역·재작성) | PowerToys · Raycast AI · ClipZ | 확산 중이나 **외부 전송**이 전제인 경우가 많다 |
| **T-3** | **스마트 감지** — 전화번호·이메일·주소·색상·URL 자동 인식 | CopyCache Pro · 다수 | 타입 판별의 확장. 액션과 연결된다 |
| **T-4** | **전문 검색(FTS)** | EcoPaste(SQLite FTS5) | 항목 수 증가에 대한 답 |
| **T-5** | **보드·컬렉션** — 작업 맥락별 묶음 | PasteBar · CopyQ 탭 | 단순 시간순 목록의 한계 극복 |
| **T-6** | **카드형 시각 타임라인** | Paste | 텍스트 목록 → 시각적 식별 |
| **T-7** | ★ **로컬 우선·프라이버시 명시** | EcoPaste(*"클라우드 동기화 없음"* 을 셀링 포인트로) | ★ **마케팅 문구가 되었다** = 사용자가 신경 쓴다 |
| **T-8** | **기기 간 동기화** | Paste(iCloud) · Win+V(MS 계정) · Ditto(LAN) | 클라우드형이 다수 |
| **T-9** | ★ **Electron 이탈 → Rust/Tauri** | EcoPaste · PasteBar | ★ 상주 앱의 무게 문제를 업계가 인정한 결과 |
| **T-10** | **생체 잠금 · 스마트 보존 정책** | 모바일 계열 다수 | 보안의 상품화 |
| **T-11** | **플로팅 버블**(모바일) | ClipZ 등 | 모바일 특유 — 데스크톱엔 해당 없음 |

### 3-1. 우리의 입장

| 흐름 | 채택 여부 | 근거 |
|---|:--:|---|
| **T-1 로컬 OCR** | 🔴 **재검토 — 채택 쪽으로 기운다** | ★ **PowerToys가 로컬 OCR로 한다**는 사실이 결정적이다 — **외부 전송이 없으므로 "로컬 전용" 원칙과 충돌하지 않는다.** 게다가 **사용자가 Maccy에서 실사용 중**이라 없으면 후퇴로 느껴진다 → **[D-7](10-decision-record.md#2-열린-결정-d--색인)** |
| **T-2 AI 변환** | ⚠️ **1차 범위 밖** | 대부분 외부 전송이 전제. 로컬 모델은 크기·의존이 [DR-8](10-decision-record.md)·[DR-9](10-decision-record.md)를 정면으로 깬다 |
| **T-3 스마트 감지** | ★ **채택** | FR-C-8(타입 판별)의 자연스러운 확장. 규칙 기반이라 비용이 거의 0 |
| **T-4 FTS** | **대체 채택** | 우리는 **인덱스 메모리 상주 + 순회**로 같은 결과를 더 싸게 낸다([06 §2-1](06-storage-design.md#2-1-인덱스-레코드--작게-유지하는-것이-전부)) |
| **T-5 보드** | ★ 채택 | FR-H-4 |
| **T-6 카드 타임라인** | ★ 채택 | 시각 언어로 계승 |
| **T-7 로컬 우선** | ★★ **기본값** | 우리는 한 발 더 — **암호화까지 기본값**([03 §6-2](03-competitive-landscape.md#6-2-nexa-clip의-자리--세-개의-차별점)) |
| **T-8 동기화** | ★ 채택 **단 P2P** | 클라우드 계정 동기화는 [DR-10](10-decision-record.md)으로 거부 |
| **T-9 Rust 전환** | ★★ **한 발 더** | Tauri도 결국 **OS WebView**에 의존한다. 우리는 **자체 CPU 래스터라이저** — 이것이 차별점 ① |
| **T-10 생체 잠금** | 채택(P2) | FR-S-6 |
| **T-11 플로팅 버블** | 해당 없음 | 모바일은 수신 전용(P3) |

> ★ **T-9가 이 표에서 가장 중요하다.** 업계가 Electron→Tauri로 한 칸 움직였는데, **Tauri도 OS마다 렌더 엔진이 다르다**(WebView2 / WKWebView / WebKitGTK). 우리는 **그 한 칸을 더 간다** — 픽셀을 직접 그려 **3-OS 동일 화면**을 만든다.

## 4. 성공 판정

> 시장 지표가 아니라 **개발자 본인의 행동**으로 판정한다.

| 단계 | 판정 |
|---|---|
| **M1 성공** | ★ macOS에서 **Maccy를 지운다** |
| **M2 성공** | ★ Windows에서 **CopyQ를 지운다** + 두 PC 사이에서 *"저쪽에 있는데"* 라는 말이 사라진다 |
| **실패 신호** | 팝업을 열었다가 **Esc를 누르고 원본을 다시 복사하러 간다** |
